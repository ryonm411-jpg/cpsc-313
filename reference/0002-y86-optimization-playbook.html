y86 Optimization Playbook

Pipeline with forwarding + branch prediction. Numbers are from the course timing model (hazards cheat sheet).

The equation

cycles ≈ instructions executed + bubbles (+ 4 to fill the pipeline) · CPI = (instr + 4 + bubbles) / instr (slides 2.5)

Two independent levers: fewer bubbles and fewer instructions. Always compare cycles. Cutting a stall-free instruction raises CPI but still saves time. Spend effort where code runs most (inner loops), because a cycle saved there is saved n times.

Legal reordering

An instruction may move past another unless they share a register as write→read (data dependency), read→write (overwriting a value that's still needed), or write→write (final value). Condition codes count as a register: every OPq writes them, and jXX/cmovXX read them. Don't slide an OPq between a flag-setter and its jump. Lesson 3.

The tricks

1 · Fill the load/use slot

before · 1 bubble

mrmovq (%rdi), %r9
addq   %r9, %rax
addq   %r8, %rdi

after · 0

mrmovq (%rdi), %r9
addq   %r8, %rdi
addq   %r9, %rax

If the filler would overwrite the register you're loading into, load into a different register.

2 · Let the arithmetic set the flags

before · 3 instr

andq %rsi, %rsi
je   base
…
subq %r8, %rsi     # n-1

after · 2 instr

subq %r8, %rsi     # n-1, sets CC
jl   base          # n-1 < 0  ⇔  n == 0
…

3 · Count down, test at the bottom

Instead of computing p − end every iteration, keep a counter that subq decrements, and end the loop with a backward jg loop. That's one test per iteration, and it's predicted taken. Guard against n ≤ 0 once, before the loop.

  andq %rsi, %rsi
  jle  done
loop:
  mrmovq (%rdi), %r10
  addq   %r8, %rdi        # %r8 = 8, hoisted out of the loop
  addq   %r10, %rax
  subq   %r9, %rsi        # %r9 = 1, hoisted
  jg     loop
done:

4 · Recursion → loop

Each recursive call costs call + ret (3 bubbles) + push/pop (often a load/use). If the recursion can be made tail-recursive (carry an accumulator, nothing left to do after the call), the call becomes a jump. For sum, n = 10: 187 → 69 cycles. Lesson 4.

5 · Shape branches for the predictor

Under BTFNT, backward = taken, forward = not taken. Put loop branches at the bottom (backward). Make forward branches jump to the rare case (an early exit, a base case, “already in order”). The common path then falls through and costs 0.

6 · Hoist constants and loads

Any irmovq of a constant, or a load of a value that doesn't change, belongs before the loop, in a register the loop doesn't otherwise use.

7 · Unroll

Process 2 (or more) elements per iteration. That pays for the counter update and branch once per 2 elements, and the second load naturally fills the first one's load/use slot. You need cleanup code for odd n. For sum, n = 10: 69 → 58 cycles. CS:APP §5.8

loop:
  mrmovq (%rdi), %r10
  mrmovq 8(%rdi), %r11
  addq   %r8, %rdi        # %r8 = 16
  addq   %r10, %rax
  addq   %r11, %rax
  subq   %r9, %rsi        # %r9 = 2
  jge    loop

Workflow (from the Lab 5 tips)

  1. Measure the baseline: instructions, bubbles by cause, cycles.
  2. Find the hot path: the inner loop of the sort runs far more than anything else.
  3. Change one thing. Keep the old version (bench: Duplicate; or a git commit).
  4. Check correctness: it still sorts, including edge cases (n = 0, 1, already sorted, reversed, duplicates). Callee-saved registers are restored. In the x86-64 convention these are %rbx %rbp %r12–%r14 (CS:APP §3.7.5; confirm against the Lab 5 handout).
  5. Record the cycle count and why it changed. Then repeat.
