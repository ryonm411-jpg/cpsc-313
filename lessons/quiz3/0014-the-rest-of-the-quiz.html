The harder version: a new line arrives before Q If the history brings in a line that isn't in the cache (call it W), there's an eviction before Q. Q10 b, c · Same cache, more ways

What moves when the ways change Keep the size and line size the same. Doubling the ways halves the sets, so one bit moves from the index to the tag. The offset never changes.
Direct-mapped → 16-way: 4 bits move. Fully associative: all index bits move, so the index is 0 bits and the mask is 0.
A stride change doesn't move any bits. It changes the hit rate only.

32-byte lines, 8 KB, 32-bit addresses:

Q10·b. 8 KB, 32-byte lines, 32-bit addresses, 16-way. Tag bits?

256 lines ÷ 16 = 16 sets → 4 index bits. 32 − 4 − 5 = 23.

Q10·c. Same cache, 16-way. Index mask?

  1. 0x1FE0
  2. 0x0F0
  3. 0x1E0
  4. 0x01F

4 ones above 5 zeros: 1 1110 0000 = 0x1E0.

Q10·d. Going from direct-mapped to fully associative, which field keeps its size?

  1. The tag
  2. The index
  3. All of them
  4. The offset

The offset depends only on the line size.

Q11 onward · Mixed review

These are mixed on purpose, the way the quiz mixes them. For each one, decide which kind of question it is before you start calculating. Each links back to its lesson.

R·1. Write-back, write-allocate, c = 1, d = 60. A write miss that evicts a dirty line?

Write back + fetch + cache write: 60 + 60 + 1 = 121. Lesson 12 §A

R·2. L1 hit 1; L1↔L2 transfer 8; L2↔memory transfer 40; all clean. 70% of accesses hit L1; 80% of L1 misses hit L2. Average in ns?

L2 hit = 8 + 1 = 9. L2 miss = 40 + 8 + 1 = 49. 0.7×1 + 0.3×(0.8×9 + 0.2×49) = 0.7 + 0.3×17 = 5.8. Remember: every path ends with the L1 hit. Lesson 4

R·3. Course MSI. This cache holds a line in M; another core reads it. New state?

  1. S, after a write-back
  2. I, after a write-back
  3. S, with no write-back
  4. M, with no change

The course's MSI diagram: a remote R/W takes M to I. (MESI would give S.) Lesson 7

R·4. Write-through, write-allocate, d = 60. A write miss?

Fetch + write to the source, with the cache write hidden: 2d = 120. No dirty lines under write-through.

R·5. 8 sets, 2-way, 32-byte lines, LRU. A line-aligned array of 19 lines is read with stride 32, 20 times. Total misses?

The cache holds 16 lines, so there are 3 extras in sets 0–2. Those sets hold 3 lines in 2 ways: 9 lines × 20 = 180. Sets 3–7: 10 lines, once each. 190. Lesson 12 §E

R·6. MESI. A core holds a line in E and writes it. What goes on the bus?

  1. An invalidate message
  2. A write to memory
  3. Nothing at all
  4. A read request

E means nobody else has it, so E → M is silent. This is MESI's whole advantage over MSI.

R·7. Write-back/allocate: hit 2, clean miss 52. Write-through/no-allocate: every write 12. Break-even hit rate?

2h + 52(1 − h) = 12, so 50h = 40 and h = 0.8.

R·8. 64 KB, 4-way, 64-byte lines. Index bits?

65536 ÷ 64 = 1024 lines; ÷ 4 = 256 sets; log₂ = 8.

R·9. A GPU runs the same instruction on thousands of pixels. Flynn class?

  1. SISD
  2. SIMD
  3. MISD
  4. MIMD

One instruction, many data. Multicore with separate programs would be MIMD.

R·10. The variable count in for (…) if (a[i] > 0) count++; shows…

  1. Temporal locality only
  2. Spatial locality only
  3. Both kinds of locality
  4. Neither kind of locality

The same address is reused on every iteration; there are no neighbours. (The array a itself is spatial only.)

R·11. Two MESI caches, the same address. Which pair is possible?

  1. M and S
  2. E and S
  3. M and E
  4. S and S

M and E mean “only I have it”, so the other cache must be I. S can pair with S or I.

R·12. A write-back cache gets a write hit. Which happens?

  1. The source is written
  2. The dirty bit is set
  3. The line is fetched
  4. The line is evicted

Only the cache is written, so its line is now dirty. The source is updated at eviction.
