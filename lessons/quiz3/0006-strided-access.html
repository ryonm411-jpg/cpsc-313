Strided Access

How far apart your accesses are decides how much of each cache line you use.

Your win for today: work out hit rates from a stride, read a stride from a trace (R3.12), and handle arrays slightly bigger than the cache (R3.13). About 25 minutes.

Warm-up: recall

A 64-byte-line cache reads one byte, then the next 63 bytes. Which locality gives those 63 hits?

  1. Spatial locality alone
  2. Temporal locality alone
  3. Both kinds of locality
  4. Neither kind of locality

Different but nearby bytes, loaded together on the first miss. Lesson 1.

1 · Stride and hit rate

Stride is the distance between consecutive accesses. For a line-aligned first pass:

Rule stride ≥ line size: every access misses.
stride < line size: one miss per line, so with L/s accesses per line, hit rate = 1 − s/L.

An int array (4 bytes), every element, 64-byte lines, cold cache. Hit rate? (4 decimals)

1 − 4/64 = 15/16.

A struct of 72 bytes, reading one field from each, 64-byte lines. Hit rate on the first pass?

The stride is 72 ≥ 64, so every access lands in a new line. This is the struct person example in slides 3.6: 20+4+20+20+6+2 = 72 bytes.

2 · 2D arrays are row-major

C stores row 0, then row 1, and so on. Walking along a row has stride = element size. Walking down a column has stride = element size × columns. Slides 3.6

double data[ROWS][TREES];   // same layout as the 1D array
for (r...) use(data[r][42]);  // stride = TREES × 8 bytes

Linh reads one tree across all times, 100 trees per row. Switching from a 1D to a 2D array in C changes the stride how?

  2. It stays at 800 bytes
  3. It rises to 1600 bytes
  4. It drops to 100 bytes

The 1D and 2D arrays have identical layouts. Only a column-major layout would help this analysis, and it would hurt Aaron's, so no layout is best for every workload.

Aaron's analysis reads about 4× more bytes than Linh's. Why did it take less time?

  1. Its access is sequential
  2. Its array is a lot smaller
  3. It uses a better policy
  4. It writes much less often

Sequential access uses whole lines, and hardware prefetches them. Linh's analysis needs a new line for every 8-byte read.

3 · Reading a stride from a trace (R3.12)

Letters are consecutive lines. Count how many accesses land in each line:

PatternMeans
A,C,E (skips lines)stride more than one line
A,B,Cexactly one line
A,A,B,C,C,D (mix of 1 and 2)between half a line and one line
A,A,B,B,C,Cexactly half a line
some lines get 3 or moreless than half a line

Now capacity. A cycle through more lines than an LRU set holds misses every time, because each line is evicted just before it's needed. A direct-mapped cache only loses the lines that collide. Try A,B,C,D,E,F, 3 passes, in a cache of 4 lines:

Fully associative LRU, 4 lines. Hits?

6 lines cycling through 4 slots: LRU always evicts the next line needed. 0/18.

Direct-mapped, 4 lines. Hits?

A,E share a slot and B,F share a slot; they keep evicting each other. C and D hit on passes 2 and 3: 2 lines × 2 passes = 4 hits.

Same trace, but the cache holds 8 lines. Which gets more hits?

  1. Fully associative LRU
  2. The direct-mapped cache
  3. It is exactly a tie
  4. Not enough information

Everything fits. Each gets 6 compulsory misses, then all hits: 12/18 for both.

4 · Slightly too big (R3.13)

A 32 KB cache: 128 sets, 8-way, 1024 lines of 32 bytes, LRU. Read a line-aligned array with stride 8 bytes, 500 times.

  1. Exactly 32 KB: every line fits, so 1024 misses in total.
  2. Extra lines wrap around. Lines are numbered 0, 1, 2…, and set = line number mod sets. Extra line number 1024 goes to set 0, the next to set 1, and so on.
  3. Each set is its own story. A set holding 9 lines in 8 ways misses on all 9, every pass. A set with 8 lines misses only once each.

The array is 1 line bigger than the cache. Which set is the new line in?

Line number 1024, and 1024 mod 128 = 0.

The array is 50 lines bigger. Which set is the last line in?

Extra lines go to sets 0 to 49. A common off-by-one is to say 50.

Still 50 extra lines, 500 passes. Total misses?

Sets 0–49 hold 9 lines each: 50 × 9 = 450 lines miss on each pass, so 450 × 500 = 225000. The other 78 sets hold 8 lines: 78 × 8 = 624 misses once. Total 225624. The stride of 8 doesn't change this, because the other accesses in a line always hit right after its miss.

Now use 64 sets and 16 ways, same size. What happens to the misses?

  1. The misses increase
  2. The misses decrease
  3. The misses stay the same
  4. Not enough information

1074 lines over 64 sets: 50 sets now hold 17 lines in 16 ways, so 850 lines miss on every pass versus 450. Total 425224. More ways doesn't help here; it makes more lines thrash together.
