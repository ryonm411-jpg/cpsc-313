Address Bits & Average Access Time

Most of the cache maths on Quiz 3 starts from two skills: splitting an address, and averaging hits with misses.

Your win for today: do the R3.4, R3.6, R3.7 and R3.8 question types without help. About 20 minutes.

1 · Why caches exist

Main memory takes about 80 ns, while L1 takes about 1.25 ns. Fast storage is expensive, so we want speed like the top of the hierarchy at a cost like the bottom. Slides 3.1

  • Order: registers → L1 → L2 → L3 → (rare L4) → main memory → SSD → disk.
  • Closer to the CPU: faster, smaller, more expensive per byte, and usually a smaller line size. Slides 3.1, 3.2
  • Temporal locality: you touch the same item again soon.
  • Spatial locality: you touch nearby items soon. This is why a cache loads a whole line, not just the bytes requested. Slides 3.2

Cache X costs more per byte than cache Y in the same system. What is most likely?

  1. X is farther from the CPU
  2. X is larger than cache Y
  3. X is closer to the CPU
  4. X is slower than cache Y

Expensive storage sits close to the CPU, where it is small and fast.

2 · Splitting an address

Address layout, high bits to low bits | tag | index | offset |
offset bits b = log₂(line size)
sets = slots ÷ associativity, and index bits s = log₂(sets)
tag bits t = address bits − s − b

In this course, 1 KB = 1024 bytes. A slot holds one line, so slots = cache size ÷ line size. Slides 3.3, 3.5; Summary of Cache Parameters

Try it: a 16 KB, 4-way cache with 32-byte lines and 40-bit addresses.

Offset bits?

log₂(32) = 5.

Slots?

16384 ÷ 32 = 512.

Index bits?

512 slots ÷ 4 ways = 128 sets, and log₂(128) = 7. The usual mistake is to use slots rather than sets here.

Tag bits?

40 − 7 − 5 = 28.

3 · Hit or miss?

  1. Split the address into tag, index and offset.
  2. Go to the set given by the index.
  3. It is a hit only if a valid slot there has the same tag. The offset then picks the byte.

The slides' tiny cache has 8-bit addresses, 8-byte lines and 4 slots, so it splits as 3 tag, 2 index and 3 offset bits. 0xBE = 101 11 110. Slides 3.2

Then the cache accesses 0xFA = 1111 1010. What happens?

  1. Hit in slot 3, tag 101
  2. Miss in slot 3, tag 111
  3. Miss in slot 2, tag 111
  4. Hit in slot 2, tag 101

111 11 010: the index is 3, the same slot as 0xBE, but the tag differs. That is a conflict, so 0xBE is evicted.

Hex shortcut: if the line size and set count are powers of 16, you can read the fields straight from the hex digits.

16 sets and 256-byte lines. Which set does 0x3A7F2 map to?

The offset is 8 bits (F2) and the index is 4 bits (7), which leaves tag 3A. The set is 7.

Drills. Get three in a row of each.

4 · Average access time and speedup

Formula average = hit rate × hit time + (1 − hit rate) × miss time
Here, miss time is the total time for a miss, including the data source, as in slides 3.2. Read the question to confirm it is defined this way.
memory speedup = old time ÷ new average time

Hit 2 ns, total miss 100 ns, hit rate 90%. Average access time in ns?

0.9 × 2 + 0.1 × 100 = 11.8.

Memory alone takes 200 ns. With a cache, a hit takes 5 ns and a total miss takes 200 ns. What hit rate gives a speedup of 5? (2 decimals)

Target average = 200 ÷ 5 = 40. Then 5h + 200(1 − h) = 40, so 195h = 160 and h ≈ 0.82.
