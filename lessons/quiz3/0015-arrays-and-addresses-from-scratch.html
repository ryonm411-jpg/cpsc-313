Arrays and Addresses, from Scratch

Q9 (hit or miss in a 2D loop) and Q10 (masks and address fields), one small step at a time.

Your win for today: draw any 2D loop on a grid, row by row or column by column, and read off every hit and miss. Then pull any field out of an address, or build an address back from its fields. Part 1 takes about 30 minutes, and Part 2 about 30. Do them on different days if you can.

Part 1 · Q9: hits and misses in a 2D loop

Step 1 · A 2D array is one long strip

Memory has no rows. C lays the array out row after row (row-major): all of row 0, then all of row 1, and so on. Slides 3.6

double a[16][16];
strip:  a[0][0] a[0][1] … a[0][15] | a[1][0] a[1][1] … a[1][15] | a[2][0] …
element:   0       1         15    |   16      17        31     |   32
Rule 1 element number of a[r][c] = (row width) × r + c. Here the row width is 16, so a[r][c] is element 16r + c.

1·1. double a[16][16]. Element number of a[1][2]?

16 × 1 + 2 = 18.

1·2. Element number of a[2][3]?

16 × 2 + 3 = 35.

Step 2 · Cache lines chop the strip into blocks of E

Rule 2 E = line size ÷ element size (char 1, int/float 4, double/long 8 bytes).
line number = ⌊element number ÷ E⌋. Lines start at columns 0, E, 2E, … in every row, as long as E divides the row width.

1·3. double, 16-byte lines. E?

16 ÷ 8 = 2. Lines hold columns [0,1], [2,3], [4,5], …

1·4. int, 32-byte lines. E?

32 ÷ 4 = 8.

1·5. double a[16][16], E = 4. Which line is a[1][3] in?

Element 19; ⌊19 / 4⌋ = 4. Line 4 holds a[1][0] to a[1][3].

1·6. E = 2. Are a[1][1] and a[1][2] in the same line?

  1. Yes, the same row
  2. No, different lines
  3. Yes, they're adjacent
  4. Only if E were 1

Elements 17 and 18: ⌊17/2⌋ = 8, ⌊18/2⌋ = 9. Being in the same row or next to each other doesn't matter; the line boundary falls between columns 1 and 2.

Step 3 · The one rule for hits and misses

Rule 3 (when the array fits in the cache) Nothing is ever evicted, so the first touch of a line is a miss, and every later touch is a hit.
Total misses = the number of different lines the loop touches.
Total hits = total accesses − total misses.
In the quiz, double a[16][16] is 2048 bytes and the cache is 2048 bytes, so it fits.

Step 4 · Draw the grid: five moves that solve every version

  1. Draw the corner of the array that the loop uses.
  2. Number the cells in the order the loop visits them (1, 2, 3, …). Unvisited cells get a dash.
  3. Draw a bar every E columns. Each block between bars is one line.
  4. Misses = blocks that contain at least one number.
  5. For a single cell: it's a miss if it has the smallest number in its block, otherwise a hit.

Try it. The explorer does those five moves for you, one access at a time. Start with the quiz's loop (it's already set up): press Step and read the line under the grid each time. Then switch “walk” to column by column and watch what changes.

Step 5 · Row by row: the quiz's loop

for (i = 0; i < 4; i++)
    for (j = i; j < 4; j++)
        sum += a[i][j];        // E = 2

Row 0 visits columns 0–3, row 1 columns 1–3, row 2 columns 2–3, row 3 column 3. With E = 2 the blocks are [0,1] and [2,3]:

RowBlock [0,1]Block [2,3]MissesHits
0a[0][0] M, a[0][1] Ha[0][2] M, a[0][3] H22
1a[1][1] Ma[1][2] M, a[1][3] H21
2—a[2][2] M, a[2][3] H11
3—a[3][3] M10

6 misses, 4 hits. Shortcut for one row from column start to end with j++: misses = ⌊end/E⌋ − ⌊start/E⌋ + 1. For row 1: ⌊3/2⌋ − ⌊1/2⌋ + 1 = 2.

When the row shortcut breaks It assumes every block between start and end gets touched. With j += 2 and E = 1, or with a step bigger than E, some blocks are skipped, so the shortcut overcounts. Count the blocks with numbers in them instead (Step 4). That always works.

1·7. E = 4, one row, j from 2 to 13 (j++). Misses in that row?

Shortcut: ⌊13/4⌋ − ⌊2/4⌋ + 1 = 3 − 0 + 1 = 4. Check with the blocks: [0–3] (via 2, 3), [4–7], [8–11], [12–15] (via 12, 13). 4 blocks.

1·8. Same row. Hits?

Accesses = 13 − 2 + 1 = 12. Hits = 12 − 4 = 8.

Step 6 · Column by column

for (i = 0; i < 4; i++)
    for (j = 0; j < 4; j++)
        sum += a[j][i];        // j picks the ROW: walking down column i

The inner loop now changes the row. Each step down jumps 16 elements, far past the end of a line, so every access in the first column lands in a new line and misses. But those lines also hold the next E − 1 columns. So when the loop moves to column 1, those cells are already loaded and hit.

E = 2, 4×4col 0col 1col 2col 3
Visit order1–45–89–1213–16
Resultall Mall hitall Mall hit
The surprise That's 8 misses and 8 hits, the same totals as row by row. When the array fits, the totals depend only on which cells are touched (Rule 3), not on the order. Order decides only which cell in each block is the miss: the earliest-numbered one.
Order does change the totals when the array doesn't fit: a column walk then evicts lines before it comes back for them. Check the sizes first.

1·9. Column by column, E = 2, square 4×4. Is a[1][0] a hit or a miss?

  1. Miss; first touch of its line
  2. Hit; a[0][0] loaded it there
  3. Hit; row 1 was loaded before
  4. Not accessed by this loop

a[1][0] is element 16, a new line. a[0][0] is in a different line (element 0).

1·10. Same loop. Is a[2][1] a hit or a miss?

  1. Miss; first touch of its line
  2. Hit; a[2][0] loaded it earlier
  3. Miss; columns never share lines
  4. Not accessed by this loop

a[2][0] and a[2][1] share a line (elements 32, 33). a[2][0] was visited in the column-0 pass, before a[2][1].

1·11. Triangle, column by column: for (i = 0; i < 4; i++) for (j = i; j < 4; j++) sum += a[j][i]; with E = 2. Misses?

The touched cells are those with row ≥ column: row 0 has column 0 (1 block), row 1 has 0–1 (1 block), row 2 has 0–2 (2 blocks), row 3 has 0–3 (2 blocks). 1 + 1 + 2 + 2 = 6.

1·12. Same loop, hits?

Accesses = 4 + 3 + 2 + 1 = 10. 10 − 6 = 4.

1·13. Square, column by column, E = 4, 8×8 (i, j < 8). Misses?

Each of the 8 rows has columns 0–7, which is 2 blocks of 4. 8 × 2 = 16. Hits = 64 − 16 = 48.

Part 2 · Q10: masks and address fields

Step 1 · Hex is just binary in groups of 4

0 00001 00012 00103 00114 01005 01016 01107 0111
8 10009 1001A 1010B 1011C 1100D 1101E 1110F 1111

To convert, swap each hex digit for its 4 bits. To go back, group the bits in fours from the right, padding the left with zeros.

2·1. 0x7C in binary?

  1. 0111 1101
  2. 0110 1100
  3. 0111 1100
  4. 1110 1100

7 = 0111, C = 1100.

2·2. 10 1110 in hex?

  1. 0xBA
  2. 0x2E
  3. 0xB8
  4. 0x5C

Group from the right: 10 | 1110 → 0010 1110 → 2E.

Step 2 · Every address is three fields

  high bits                                  low bits
[      tag      |    index    |   offset   ]
                   s bits        b bits
b = log₂(line size)    s = log₂(sets)    tag = everything left

sets = cache size ÷ line size ÷ ways. The offset says which byte inside the line; the index says which set; the tag tells lines in the same set apart. Slides 3.2, cache parameters sheet

Step 3 · Masks: ones where the field is

Three masks offset mask = line − 1 (b ones at the bottom)
index mask = (sets − 1) × line (s ones sitting above b zeros)
tag mask = all the remaining high bits: 2³² − sets × line for 32-bit addresses
field = (address AND mask) shifted right by the number of bits below it.

Worked: 16 KB, 4-way, 64-byte lines. Sets = 16384 ÷ 64 ÷ 4 = 64, so b = 6 and s = 6.

  • Offset mask: 11 1111 = 0x3F
  • Index mask: 1111 1100 0000 = 0xFC0
  • Tag mask: 1111 … 1111 0000 0000 0000 = 0xFFFFF000

2·3. 4 KB direct-mapped, 32-byte lines. Index mask?

  1. 0x7F
  2. 0x1F
  3. 0xF80
  4. 0xFE0

128 sets → 7 ones above 5 zeros: 1111 1110 0000 = 0xFE0. 0x7F is “7 ones” without the shift, a common slip.

2·4. Same cache. Tag mask (32-bit)?

  1. 0xFFFFF000
  2. 0xFFFFFF80
  3. 0x00000FFF
  4. 0xFFFFFFE0

The index and offset take the low 12 bits, so the tag is the top 20: 0xFFFFF000.

Step 4 · Pull the fields out of an address

Worked with your drill's problem: 2-way, 2 KB, 16-byte lines, address 0xCB6EEC.

  1. Sets = 2048 ÷ 16 ÷ 2 = 64. So b = 4 and s = 6. Index mask = 63 × 16 = 0x3F0.
  2. Write the low hex digits in binary: 0x…EEC = 1110 1110 1100.
  3. Offset = the low 4 bits = 1100 (0xC = 12).
  4. Index = the next 6 bits: 1110 1110 1100 → drop 1100 → 1110 1110 → keep 6 → 10 1110 (0x2E = 46).
  5. Tag = everything above the low 10 bits = 0x32DB.

2·5. 8 KB, 2-way, 32-byte lines (128 sets). Index of 0x12345678, in hex?

  1. 0x78
  2. 0x33
  3. 0x56
  4. 0x2B3

…0101 0110 0111 1000. Drop 5 offset bits → …0101 0110 011. Keep 7 → 011 0011 = 0x33.

Step 5 · Build an address back (like R3.6)

Glue the fields together address = (tag × sets + index) × line + offset, which is tag bits, then index bits, then offset bits, written side by side.

Worked: 4 KB direct-mapped, 32-byte lines (s = 7, b = 5, so 12 low bits). Tag 0x1A2B, set 5, byte 9. The low 12 bits are index 000 0101 then offset 0 1001: 0000 1010 1001 = 0x0A9. The tag goes on top: 0x1A2B0A9.

2·6. Same cache. Tag 0x1A2B, set 5. Address of the first byte of that line?

  1. 0x1A2B005
  2. 0x1A2B0A9
  3. 0x1A2B0A0
  4. 0x01A2B05

Offset 0: index 5 shifted up 5 bits = 0xA0, so 0x1A2B0A0.

Step 6 · Work backwards from the bit counts (like R3.4)

Line = 2^b. Sets = 2^s. Lines = sets × ways. Size = lines × line size.

2·7. 32-bit addresses split 19 tag / 7 index / 6 offset; 2-way. Cache size in bytes?

Line = 64, sets = 128, lines = 256, size = 256 × 64 = 16384 (16 KB).

2·8. Same cache made 4-way, same size. Tag bits now?

Sets halve to 64, so the index drops to 6 bits and the tag gains that bit: 32 − 6 − 6 = 20.

Step 7 · Same set? Same line?

Compare fields Same set = same index; the two lines compete for that set's ways.
Same line = same tag and the same index; only the offset differs, so one load brings in both.

8 KB, 2-way, 32-byte lines: 0x12345678 has index 0x33 and tag 0x12345.

2·9. 0x12347678 vs 0x12345678?

  1. Same set, same line
  2. Same set, different line
  3. Different set, same tag
  4. Different set and tag

Index 0x33 for both; tags 0x12347 and 0x12345.

2·10. 0x12345668 vs 0x12345678?

  1. Same set, same line
  2. Same set, different line
  3. Different set, same tag
  4. Different set and tag

They differ only in the low 5 bits (0x68 vs 0x78 share bits 5 and up), so they're in the same line.

2·11. 0x12345688 vs 0x12345678?

  1. Same set, same line
  2. Same set, different line
  3. Different set, same tag
  4. Different set and tag

0x688 has index 0x34, the next set. Same tag 0x12345.
