1 · Properties to bits (R3.4)

Method offset b = log₂(line size) · lines = size ÷ line size · sets = lines ÷ ways · index s = log₂(sets) · tag t = address bits − s − b.
To go the other way: size = 2s × ways × 2b.

1.1

A 2-way, 16 KB cache has 32-byte lines and 32-bit addresses. How many tag bits?

b = 5. 16384 ÷ 32 = 512 lines. ÷ 2 = 256 sets, so s = 8. t = 32 − 8 − 5 = 19.

1.2

A 4-way, 256 KB cache has 128-byte lines. How many lines does it hold?

262144 ÷ 128 = 2048.

1.3

Same cache, 48-bit addresses. How many tag bits?

2048 ÷ 4 = 512 sets, so s = 9. b = 7. t = 48 − 9 − 7 = 32.

1.4

A direct-mapped cache has 10 index bits and 6 offset bits. What is its size in KB?

2¹⁰ sets × 1 way × 2⁶ bytes = 65536 bytes = 64 KB.

1.5

A 4-way cache has 12 index bits and 5 offset bits. What is its size in KB?

4096 × 4 × 32 = 524288 bytes = 512 KB.

1.6

A fully associative 8 KB cache has 64-byte lines and 32-bit addresses. How many tag bits?

Fully associative means one set, so s = 0. t = 32 − 0 − 6 = 26.

2 · Changing parameters (R3.5)

Two equations that must stay true address bits = t + s + b · size = sets × ways × line size. Change one value, then work out what else has to move to keep both equations true.

2.1

Halve the cache size, keeping the ways, the line size and the address width fixed. What happens?

  1. index −1, offset same, tag +1
  2. index same, offset −1, tag +1
  3. index −1, offset +1, tag same
  4. index +1, offset same, tag −1

Half as many lines with the same ways gives half as many sets.

2.2

Double the ways and double the size, keeping the line size fixed. What happens?

  1. index −1, tag +1
  2. index +1, tag −1
  3. offset +1, tag −1
  4. All the bit counts stay the same

Sets = size ÷ (ways × line). Both the top and the bottom double, so the number of sets doesn't change.

2.3

Add one offset bit, keeping the index bits, the ways and the address width fixed. Which must be true?

  1. The tag gains a bit, and the size stays the same
  2. The tag loses a bit, and the size doubles
  3. The tag stays the same, and the size halves
  4. The tag loses a bit, and the size stays the same

t = width − s − b, so t goes down by 1. Lines are twice as large, with the same sets and ways, so the cache doubles.

2.4

The tag loses one bit, keeping the line size and the address width fixed. Which must be true?

  1. The line size doubles
  2. The ways must double
  3. The number of sets doubles
  4. The cache size halves

b is fixed, so the bit must go to the index, which doubles the number of sets. The size or the ways could change either way to make that happen, so neither is forced.

3 · Write-through vs write-back (R3.10)

3.1

Write-back, write-allocate: hit 2, clean miss 22. Write-through, no-allocate: every write 10. All evictions clean. Break-even hit rate? (2 decimals)

2h + 22(1 − h) = 10, so 22 − 20h = 10, 20h = 12 and h = 0.60.

3.2

Write-back, write-allocate with c = 2, d = 20, and half of all misses evict a dirty line. Write-through, no-allocate costs 20 for every write. Break-even hit rate? (2 decimals)

Clean miss = c + d = 22. Dirty miss = c + 2d = 42. Average miss = 0.5×22 + 0.5×42 = 32. Then 2h + 32(1 − h) = 20, so 30h = 12 and h = 0.40.

3.3

In 3.2 the real hit rate is 0.90. Which is faster?

  1. Write-back is faster
  2. Write-through is faster
  3. They are exactly equal
  4. It depends on the reads

Above the break-even rate, the cheap write-back hits win: 0.9×2 + 0.1×32 = 5, compared with 20.

3.4

Write-back, write-allocate: hit 1, clean miss 41. Write-through, no-allocate: every write 11. All evictions clean. Break-even hit rate? (2 decimals)

h + 41(1 − h) = 11, so 40h = 30 and h = 0.75.

4 · Stride and throughput (R3.11)

Rule For one cold, line-aligned pass with stride smaller than the line: accesses per line = line ÷ stride, and hit rate = 1 − stride ÷ line. If the stride is at least one line, every access misses.

4.1

int a[N] (4-byte ints), 64-byte lines, read once with stride 1 element. Hit rate? (4 decimals)

16 ints per line: 1 miss and 15 hits. 15/16 = 0.9375.

4.2

Same array, read with stride 4 elements. Hit rate?

Stride 16 bytes gives 4 accesses per line: 1 miss and 3 hits.

4.3

Same array, read with stride 32 elements. Hit rate?

The stride is 128 bytes, more than one line, so every access hits a new line.

4.4

long a[1000][1000], with the loop for (j…) for (i…) sum += a[i][j];. Stride in bytes?

The inner loop changes i, which moves down a column. In row-major order that is one whole row: 1000 × 8 = 8000.

4.5

How do you get spatial locality back in 4.4?

  1. Use a bigger cache with the same line
  2. Swap the loops, so j is the inner loop
  3. Change the replacement policy to LRU
  4. Make the cache fully associative

With j inner, the stride is 8 bytes, so each line gives 8 accesses.

4.6

Program X reads 4× as many bytes as Program Y but finishes sooner. What is the most likely reason?

  1. X uses write-through
  2. X has more temporal locality
  3. X reads sequentially, and Y strides by a row
  4. Y's array is too small to cache

Sequential access uses whole lines, and the hardware prefetches them. Y fetches a new line for every element it reads.

5 · Abstract stride and policies (R3.12)

Reading a trace Letters are consecutive lines. Count the accesses that land in each line: 1 per line means one line exactly · skipped letters mean more than one line · always 2 means half a line · 2 or 3 means under half a line · a mix of 1 and 2 means between half a line and one line.

5.1

Trace A,A,B,B,C,C,D,D. What is the stride?

  1. More than one line
  2. Exactly one line
  3. Exactly half a line
  4. Under half a line

Exactly 2 accesses per line.

5.2

Trace A,C,E,G,I. What is the stride?

  1. More than one line
  2. Exactly one line
  3. Exactly half a line
  4. Under half a line

Lines are skipped.

5.3

Trace A,B,B,C,D,D,E. What is the stride?

  1. Exactly one line
  2. Between half a line and one line
  3. Exactly half a line
  4. Under half a line

A mix of 1 and 2 accesses per line.

For 5.4 to 5.7: the trace (A,B,C,D,E) repeats 3 times, with 15 accesses in all. A–E are consecutive lines, and A falls in slot 0. The cache holds 4 lines.

5.4

Fully associative, LRU. How many hits?

5 lines go round in a cycle through 4 slots. LRU always evicts the line that comes back next, so you get 0 hits.

5.5

Direct-mapped. How many hits?

A and E share slot 0 and keep evicting each other. B, C and D hit on passes 2 and 3: 3 × 2 = 6.

5.6

Fully associative, Belady (optimal). How many hits?

Misses on A, B, C, D. E evicts D, because D is used farthest away. Then A, B and C hit. D evicts C. E, A and B hit. C evicts A (A is never used again). D and E hit. 3 + 3 + 2 = 8 hits.

5.7

Now the trace is (A,B,C,D) × 3 in the same 4-line cache. Which gets more hits?

  1. Fully associative LRU
  2. Direct-mapped
  3. It is a tie
  4. Not enough information

Everything fits in both. Each has 4 cold misses and 8 hits.

6 · Arrays slightly too big (R3.13)

The cache is 64 KB and 8-way with 64-byte lines, so it has 1024 lines in 128 sets, and uses LRU. A line-aligned array is read with stride 8 bytes (8 accesses per line), 200 times.

6.1

The array is exactly 64 KB. Total misses?

Every line fits, so there are only cold misses: 1024.

6.2

The array is 640 bytes bigger. How many sets thrash?

640 ÷ 64 = 10 extra lines, numbered 1024–1033. They go to sets 0–9.

6.3

Same oversized array. Total misses?

10 sets each hold 9 lines in 8 ways, so those 90 lines miss on every pass: 90 × 200 = 18000. The other 118 sets hold 944 lines, and each misses once. Total 18944. The other 7 accesses in each line always hit.

6.4

Same size, but the cache is now 16-way (64 sets). Total misses?

The extra lines still go to sets 0–9, but now each of those sets holds 17 lines in 16 ways, so 170 lines thrash: 34000. The other 54 sets hold 864 lines, which miss once. Total 34864.

6.5

Same size, but the cache is now direct-mapped (1024 sets). Total misses?

Lines 0–9 clash only with lines 1024–1033, so 20 lines miss on every pass: 4000. The other 1014 lines miss once. Total 5014.

6.6

For a cyclic array that is slightly too big, what does more associativity (same size, LRU) do to misses?

  1. Decreases them
  2. Increases them
  3. No change at all
  4. Depends on stride

More ways means more lines share each overflowing set, and LRU throws all of them out on every pass. Direct-mapped 5014 < 8-way 18944 < 16-way 34864.

7 · MESI pairings (R3.14)

Rule Same address: M and E are exclusive, so they pair only with I. Valid pairs are I with anything, or S with S.
Same slot or index only: the tags may differ, which makes them different lines, so any pair is possible.

7.1

Two MESI caches, same address. Which pair is impossible?

  1. S and S
  2. I and I
  3. M and I
  4. E and S

E means the only copy, so another cache can't hold the line in S at the same time.

7.2

Two MESI caches, same address. Which pair is possible?

  1. M and S
  2. E and E
  3. I and E
  4. M and M

I can pair with anything.

7.3

Two MESI caches, same index, with no statement about tags. Which pair is impossible?

  1. M and M
  2. E and S
  3. M and E
  4. None of them

The tags may differ, which makes them different lines with unrelated states.

7.4

Three MESI caches, same address. Which combination is possible?

  1. E, S, I
  2. S, S, I
  3. M, S, S
  4. M, I, E

Any number of S copies can exist, and I fits with anything. M or E would require every other cache to be I.

8 · MSI vs MESI transitions (R3.15)

The differences Course MSI: M → I on a remote read. MESI: M → S (after a write-back).
A read miss with no other copies gives S in MSI but E in MESI.
Read hits never change state, a local write always ends in M, and a remote write always ends in I.

8.1

Course MSI. Core 1 holds a line in M, and Core 2 reads it. What is Core 1's new state?

  1. I, after a write-back
  2. S, after a write-back
  3. S, with no write-back
  4. M, with no change

This is the course MSI diagram. Watch for it on the quiz.

8.2

MESI. Same situation: Core 1 holds the line in M, and Core 2 reads it. Core 1's new state?

  1. I, after a write-back
  2. S, after a write-back
  3. S, with no write-back
  4. E, with no write-back

Both cores can now share the line, once the dirty data has been written back.

8.3

Core 1 holds a line in M. Which event leaves Core 1 in a different state under MSI than under MESI?

  1. Core 1 read hit
  2. Core 1 write hit
  3. Core 2 reads line
  4. Core 2 writes line

MSI gives I and MESI gives S. Each of the others gives the same result in both protocols: M, M and I.

8.4

Core 1 holds a line in S. Which event leaves Core 1 in a different state under MSI than under MESI?

  1. None of these
  2. Core 1 write hit
  3. Core 2 reads line
  4. Core 2 writes line

From S, both protocols do the same thing: a local write → M, a remote read → S, a remote write → I.

8.5

Core 1 reads a line that no other cache holds. What state does it get in MSI and in MESI?

  1. S and S
  2. S and E
  3. E and E
  4. M and E

MSI has no E state. MESI marks the only clean copy as E.

8.6

MESI. Core 1 holds a line in E, and Core 2 writes it. What is Core 1's new state?

  1. S, with no write-back
  2. M, with no write-back
  3. I, with no write-back
  4. I, after a write-back

A remote write always invalidates. E is clean, so there is nothing to write back.

8.7

MESI. Core 1 holds a line in S and writes it. What happens?

  1. S → M, after broadcasting an invalidate
  2. S → M, with no bus message
  3. S → E, then E → M
  4. It stays S and writes through

Other cores might have copies, so they must be invalidated. Only E → M is silent.
