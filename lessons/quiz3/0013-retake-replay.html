Q3 · Stride and miss rate

You walk through an array that is much bigger than the cache, so nothing is reused and every line is touched once. With line size L and stride S:

Three cases S < L: each line takes L/S accesses and misses once, so the miss rate is S/L.
S ≥ L: every access lands in a new line, so the miss rate is 1.
So changing S only changes the miss rate while S is still below L. Once S ≥ L, making it bigger leaves it at 1.
Check your memory of Q3a You remember the answer to “S doubles” as stays the same. That's right only if S was already ≥ 64. If S was, say, 8, doubling it doubles the miss rate (1/8 → 1/4). On the retake, look for the size of S before you answer. Slides 3.6

Q3·1. 64-byte lines, huge array, stride 8 bytes. The stride doubles. The miss rate…

  1. doubles, 1/8 to 1/4
  2. stays the same at 1/8
  3. halves, 1/8 to 1/16
  4. becomes exactly one

S/L: 8/64 → 16/64. Twice as few accesses per line, and still one miss per line.

Q3·2. 64-byte lines, huge array, stride 64 bytes. The stride doubles. The miss rate…

  1. doubles, 1 to 2
  2. stays the same at 1
  3. halves, 1 to 1/2
  4. drops below one half

Every access already misses. A rate can't go above 1.

Q3·3. 64-byte lines, huge array, stride t > 64. The stride triples. The miss rate…

  1. triples from its old value
  2. drops to a third of it
  3. rises but stays under one
  4. stays the same at one

t > L means every access is already a new line.

Q3·4 (harder). 64-byte lines, huge array, stride 40 bytes. The stride doubles to 80. The miss rate…

  1. doubles from 0.625 to 1.25
  2. stays the same at 0.625
  3. rises from about 0.63 to 1
  4. halves to about 0.31

40 < 64, so the rate is about 40/64 ≈ 0.63. 80 ≥ 64, so every access misses: 1. It can't double past 1.

Q3·5. 64-byte lines, huge int array (4 bytes), every element read once. Miss rate? (4 decimals)

S/L = 4/64 = 0.0625.

Q4 · What's in the memory hierarchy?

The course's list, from fastest and smallest to slowest and biggest Slides 3.1, slide 8:

Registers → L1 cache → L2 cache → L3 cache → (L4 cache, rare) → Main memory → Solid-state (flash) drive → Disk drive

Each level acts as a cache for the level below it. The test: does it store data? Parts that compute or control (ALU, decoder, branch predictor) aren't levels.

Q4·1. Select every item that is part of the memory hierarchy.

  1. Registers
  2. The ALU
  3. Flash drive
  4. Main memory
  5. Branch predictor
  6. Disk drive

Registers, flash (SSD), main memory and disk all store data at a level. The ALU computes; the branch predictor guesses jumps.

Q4·2. Which pair is in the right order, faster level first?

  1. Flash drive, then L3
  2. L2 cache, then DRAM
  3. Disk drive, then flash
  4. Main memory, then L1

Going down the list means bigger, cheaper per byte and slower.

Q4·3. Going down the hierarchy, each level gets…

  1. smaller, faster, pricier
  2. bigger, faster, cheaper
  3. smaller, slower, cheaper
  4. bigger, slower, cheaper

Cost per byte drops and size grows as you move away from the CPU. Slides 3.1, size/latency/price slides

Q5 · Is Belady always better?

Optimal ≠ always strictly better Belady (evict the line used furthest in the future) is optimal: no policy ever gets fewer misses. But other policies can tie it, for example when everything fits in the cache, or when LRU happens to make the same choices. So “Belady is always more optimal than X” is false for every X, which makes the answer none of the above. Slides 3.3, slides 12–14

Q5·1. Belady's algorithm is always strictly better (fewer misses) than which policy?

  1. LRU
  2. LFU
  3. Random
  4. None of the above

Any of them can tie Belady on some sequence. Try A, B, A, B with 2 slots: every policy gets 2 misses.

Q5·2. Which statement about Belady is true?

  1. It never has more misses than any policy
  2. It always has fewer misses than LRU does
  3. It can be built into real hardware caches
  4. It evicts the line used furthest in the past

It needs the future, so it can't be built. It's the yardstick. “Furthest in the past” is LRU.

Q5·3. 4 slots, sequence A B C D A B C D. How many misses does LRU get? (Belady gets 4.)

4 lines fit in 4 slots, so only cold misses: 4. A tie, which is why “always better” fails.

Q6 · Random eviction: maximum misses

The opposite of Belady For the maximum, assume the worst luck: on every miss, evict the line that's needed soonest. Then count.
A repeat is a guaranteed hit when (a) the cache wasn't full yet, or (b) no miss happened since that line was last used.
If the number of distinct lines ≤ slots, nothing is ever evicted, so the maximum equals the minimum.

Worked: 3 slots, A B C A D A B C D.

AccessABCADABCD
ResultMMMhitMMMMM
EvictABCD

A at position 4 must hit: the cache had just filled up and nothing missed in between. Maximum = 8. Belady gets 5.

Q6·1. Same sequence, but 4 slots. Maximum misses?

Only 4 distinct lines, so they all fit and nothing gets evicted: 4.

Q6·2. 4 slots, A B A C D B A E B A. Maximum misses with random eviction?

A B (A hits) C D: 4 misses, and the cache is full. B, then A: both hit, because no miss happened since. E misses and evicts B (needed next). B misses and evicts A. A misses. 4 + 3 = 7.

Q6·3 (harder). Same sequence and slots. Minimum misses (Belady)?

E evicts C or D (never used again). B and A then hit. 5.

Drill. It asks for compulsory, maximum (random) and minimum (Belady), because a harder version might ask for more than one.

Q7 · Working backwards to the dirty rate

Write-back, write-allocate, with cache time c, memory time d, miss rate m, and a fraction p of evictions that are dirty. Count the trips (Lesson 12): hit = c, clean miss = c + d, dirty miss = c + 2d.

Build it, then solve for p T = (1 − m)·c + m·[(1 − p)(c + d) + p(c + 2d)]
  = c + m·d·(1 + p)
so p = (T − c) / (m·d) − 1

Worked: c = 2, d = 50, m = 0.1, T = 9.5. (9.5 − 2) / (0.1 × 50) − 1 = 7.5/5 − 1 = 0.5.

Sanity check: if p is negative or bigger than 1, you've made a mistake. The usual one is forgetting that c is paid on misses too.

Q7·1. c = 1, d = 100, m = 0.05, T = 7. Dirty fraction?

(7 − 1) / 5 − 1 = 1.2 − 1 = 0.2.

Q7·2. c = 4, d = 40, m = 0.2, T = 18. Dirty fraction?

(18 − 4) / 8 − 1 = 1.75 − 1 = 0.75.

Q7·3 (harder, solve for m). c = 2, d = 50, 25% of evictions dirty, T = 7. Miss rate?

T = c + m·d·(1 + p): 7 = 2 + m × 50 × 1.25 = 2 + 62.5m, so m = 5/62.5 = 0.08.

Q8 · Amdahl, two parts

One formula new-time fraction = f/s₁ + (1 − f)/s₂  ·  speedup = 1 / that  ·  new time = old × that
If a change makes a part slower, its s is less than 1 (for example 0.9), and the same formula still works. Amdahl reference sheet

From your notes: f = 0.52 memory at 3.6×; if the rest is 1.4× (from your first recall), then 0.52/3.6 + 0.48/1.4 = 0.48730.

Q8·1. Speedup? (4 decimals)

1 / 0.48730 = 2.0521.

Q8·2. The old time was 132 s. New time? (2 decimals)

132 × 0.48730 = 64.32 s. Or 132 / 2.0521.

Q8·3 (harder). Same, but the memory change makes non-memory work slower: 0.9× its old speed. New time for 132 s? (2 decimals)

0.52/3.6 + 0.48/0.9 = 0.14444 + 0.53333 = 0.67778. 132 × 0.67778 = 89.47 s. The speedup is only 1.4754.

“52% of instructions” Amdahl needs the fraction of time. If the question says instructions and gives no per-instruction times, treat them as equal and use 0.52. If it gives times (for example, memory instructions take 3 cycles and others take 1), turn them into a time fraction first: 0.52×3 / (0.52×3 + 0.48×1).

Q9 · The triangle loop

int sum = 0;  double arr[16][16];      // 2048 bytes = the whole cache
for (i = 0; i < 4; i++)
    for (j = i; j < 4; j++)
        sum += arr[i][j];
  1. Elements per line E = line bytes ÷ element bytes. Your note “arr[0][1] and then every other one hits” fits E = 2 (16-byte lines with doubles).
  2. arr[i][j] is element 16·i + j, in line ⌊(16·i + j) / E⌋. The first touch of a line misses; later touches hit.
  3. Watch where each row starts. j starts at i, so row 1 starts at arr[1][1], which is in the second half of a line when E = 2. It's still a miss, because arr[1][0] was never loaded.
  4. The array fits in the cache (2048 = 2048), so there are no conflicts; every miss is a cold miss. sum is in a register.
E = 2j = 0j = 1j = 2j = 3
i = 0MhitMhit
i = 1—MMhit
i = 2——Mhit
i = 3———M

E = 2: 4 hits, 6 misses. If the lines hold 4 elements (E = 4), each row's first access misses and the rest hit: 6 hits, 4 misses.

Q9·1. E = 2. Is arr[1][2] a hit or a miss?

  1. Hit; row 1 was loaded
  2. Hit; arr[1][1] loaded it
  3. Miss; it's a new line
  4. Not accessed by the loop

arr[1][1] is element 17, in line 8 with element 16. arr[1][2] is element 18, in line 9. New line, so it misses.

Q9·2. E = 2, but now i < 16 and j < 16 (j still starts at i): 136 accesses. Misses?

Row i touches lines ⌊i/2⌋ to 7 of that row: 8 − ⌊i/2⌋ lines. The sum over i = 0…15 is 2 × (8+7+…+1) = 72. Hits = 136 − 72 = 64.

Q9·3. Same as Q9·2 but E = 4. Misses?

Row i touches 4 − ⌊i/4⌋ lines. The sum is 4 × (4+3+2+1) = 40. Hits = 96.

Q9·4. Change j++ to j += 2. Compared to j++, the misses and the hits…

  1. misses rise, hits stay
  2. misses stay, hits drop
  3. both of them go down
  4. both of them go up

A stride of 2 elements is still ≤ one line, so the same lines get touched: same misses (E = 2: 72; E = 4: 40). There are fewer accesses per line, so fewer hits (E = 2: 0; E = 4: 32). The miss rate rises.

About your “122 times” A full 16×16 triangle (j from i) runs 136 times. With i < 4 and j < 16, it runs 58 times. 122 doesn't match either, so on the retake, count it yourself: Σ (row length − starting j), divided by the step.

Drill: random loops, line sizes and steps. The answer shows every hit and miss.

Q10 · The index mask in hex

Recipe offset bits b = log₂(line). Index bits s = log₂(sets).
mask = (sets − 1) << b: s ones sitting above b zeros. Write it in binary, then group in 4s from the right to get hex.
index = (address & mask) >> b, written with exactly s bits.

Worked: 32-byte lines (b = 5), 8 KB direct-mapped → 256 sets (s = 8). Mask = 1111 1111 followed by 00000 = 1 1111 1110 0000 = 0x1FE0.
Address 0x0040B7C4: the low bits are …1011 0111 1100 0100. Drop the 5 offset bits (00100) and keep the next 8: 1011 1110 (0xBE).

Q10·1. Same cache made 2-way (128 sets). Index mask?

  1. 0xFE0
  2. 0x1FE0
  3. 0x7F0
  4. 0xFF0

7 ones above 5 zeros: 1111 1110 0000 = 0xFE0. The index loses its top bit to the tag.

Q10·2. 2-way: the index of 0x0040B7C4 in binary?

  1. 1011 1110
  2. 101 1111
  3. 011 1110
  4. 111 1100

The same bits as before, minus the top one: 0111110.

Q10·3. Fully associative, 32-byte lines. Index mask?

  1. 0x1F
  2. 0xFE0
  3. 0xFFFFFFE0
  4. 0x0 (no index)

One set means no index bits. 0x1F is the offset mask, a common mix-up.

Q10·4. 32-byte lines. Which mask picks out the offset?

  1. 0x20
  2. 0x1F
  3. 0x3F
  4. 0x10

Offset = the low 5 bits = 11111 = 0x1F.
