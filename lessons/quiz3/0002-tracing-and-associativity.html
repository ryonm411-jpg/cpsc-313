Tracing Hits & Misses, and Associativity

Each set is its own small cache. Once you see that, tracing becomes mechanical.

Your win for today: trace a list of addresses through a direct-mapped or 2-way cache, and reason about changes to its parameters (R3.5). About 20 minutes.

Warm-up: recall

A 2-way, 4 KB cache has 16-byte lines. How many index bits?

4096 ÷ 16 = 256 slots. 256 ÷ 2 = 128 sets. log₂(128) = 7.

1 · One cache, three shapes

ShapeSetsSlots per setA line can go in
Direct-mappedn1exactly 1 slot
k-way set associativen/kkany of k slots in 1 set
Fully associative1nany slot (0 index bits)

A direct-mapped cache is “1-way”, and each set behaves like its own little fully associative cache. The number of sets must be a power of 2; the number of ways need not be. Slides 3.3

2 · Worked trace

16-byte lines mean the last hex digit is the offset, so 0x04 is in the same line as 0x00. Trace 0x00, 0x04, 0x10, 0x40, 0x00, 0x44:

AddressLineDirect-mapped, 4 sets2-way LRU, 2 sets
0x000x00set 0: missset 0: miss
0x040x00set 0: hitset 0: hit
0x100x10set 1: missset 1: miss
0x400x40set 0: miss, evicts 0x00set 0: miss, both fit
0x000x00set 0: miss, evicts 0x40set 0: hit
0x440x40set 0: miss, evicts 0x00set 0: hit

Same size, but 1/6 hits versus 3/6. Lines 0x00 and 0x40 take turns evicting each other in the direct-mapped cache.

Kinds of miss Compulsory: first access to that line, ever.
Capacity: the cache is too small for what you are using. Slides 3.3
Conflict: there was room elsewhere, but the line's set was full, as with 0xBE and 0xFA. Slides 3.2

In the direct-mapped column, what kind of miss is the second access to 0x00?

  1. A compulsory miss
  2. A conflict miss
  3. A capacity miss
  4. A cold-start miss

It was cached before, and slots 2 and 3 were free. Only the mapping forced the eviction.

Drill. Do five. Mark the hits first, then check.

3 · Changing parameters (R3.5)

Two equations that must stay true address bits = t + s + b
cache size = sets × ways × line size

Change one value, then ask what must move to keep both true. Fewer index bits means fewer sets. So tag or offset bits must grow, and to keep the second equation true the size must shrink, or the ways or line size must grow.

You increase the index bits, keeping the address width fixed. Which change can be part of a sensible way to keep things consistent?

  1. The associativity increases
  2. The tag bits are increased
  3. The overall size increases
  4. The line size is increased

More sets with the same ways and line size means a bigger cache. Index bits went up, so tag or offset bits must go down, which rules out the tag and line-size options. More ways would grow the cache even further and doesn't help anything.

Double the line size, keeping the size and ways fixed. What happens to the bits?

  1. offset +1, index −1, tag same
  2. offset +1, index same, tag −1
  3. offset −1, index +1, tag same
  4. offset +1, index +1, tag −2

Twice the line size gives half as many slots, so half as many sets. One bit moves from index to offset.

Which is not stored as metadata in a slot of a write-back, set-associative LRU cache?

  1. The valid bit
  2. The dirty bit
  3. The index bits
  4. The tag bits

The index is implied by which set the slot sits in. Slides 3.5 list valid, tag, dirty and replacement information.
