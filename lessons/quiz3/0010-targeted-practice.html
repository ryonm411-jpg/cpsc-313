Targeted Practice

Built from the questions you missed on the mock quiz, with new numbers.

The write rule With c = cache time and d = source time:
Write-through: the cache write runs at the same time as the source write, so c is hidden. A hit costs d, and a write-allocate miss costs 2d.
Write-back: c is always added. A hit costs c, a clean miss costs c + d, and a dirty miss costs c + 2d.
How to take it Use paper, a calculator and the cache parameters and MESI sheets. Write your reasoning before you check. Group A carries the most weight, because write policies cost you the most points on the mock.

A · Writes (c = 2, d = 30)

A1

Write-through, no-write-allocate. Latency of a write miss in ns?

The miss goes straight to the source, and the cache does nothing. A hit also costs 30, because c is hidden behind d.

A2

Write-through, write-allocate. Latency of a write miss in ns?

2d = 30 + 30: one source write for the data, plus one source read to fetch the line. The cache time stays hidden.

A3

Write-back, write-allocate. A write miss with a clean eviction, in ns?

c + d = 2 + 30. Fetch the line, then write into the cache.

A4

Write-back, write-allocate. A write miss with a dirty eviction, in ns?

c + 2d = 2 + 30 + 30. Write the dirty line back, fetch the new one, then write into the cache. On the mock you left off the c.

A5

Write-back, write-allocate, c = 2, d = 30. 90% of writes hit, and 40% of the misses evict a dirty line. Average write time in ns? (2 decimals)

Average miss = 0.6×32 + 0.4×62 = 44. Average = 0.9×2 + 0.1×44 = 1.8 + 4.4 = 6.20.

A6

Write-back, write-allocate: hit 3, clean miss 33. Write-through, no-allocate: every write 12. All evictions clean. Break-even hit rate? (2 decimals)

3h + 33(1 − h) = 12, so 33 − 30h = 12, 30h = 21 and h = 0.70.

A7

A program appends to a 10 GB log file that is never read back. Which miss policy suits it best?

  1. Write-allocate
  2. No-write-allocate
  3. Allocate on read only after a write
  4. Allocate whichever line is LRU

Loading lines that are never read just pushes useful data out of the cache.

A8

A program increments one counter a million times. Which write policy sends the fewest writes to the source?

  1. Write-back
  2. Write-through
  3. The same for both
  4. It depends on associativity

Write-back coalesces the writes: the line goes to the source once, on eviction. Write-through sends a million source writes.

B · Multi-level (L1 hit 2; L1↔L2 transfer 10; L2↔memory transfer 50; write-back)

B1

60% of accesses hit L1. Of the L1 misses, 75% hit L2. All evictions are clean. Average in ns? (2 decimals)

Every path ends with the L1 hit. L1 hit = 2. L2 hit = 10 + 2 = 12. L2 miss = 50 + 10 + 2 = 62.
0.6×2 + 0.4×(0.75×12 + 0.25×62) = 1.2 + 0.4×24.5 = 11.00.

B2

A read misses L1 and evicts a dirty line, then misses L2 and evicts a clean line. Time in ns?

10 (write the dirty L1 line back) + 50 (fetch from memory) + 10 (move to L1) + 2 (L1 hit) = 72.

B3

A read misses L1 and evicts a dirty line, then hits L2. Time in ns?

10 (write back) + 10 (fetch) + 2 (hit) = 22.

C · Bits

C1

An 8-way, 128 KB cache has 32-byte lines. How many index bits?

Lines → sets → log₂. 131072 ÷ 32 = 4096 lines. ÷ 8 = 512 sets. log₂(512) = 9.

C2

Same cache, 40-bit addresses. How many tag bits?

Offset = log₂(32) = 5. Tag = 40 − 9 − 5 = 26.

C3

Keep the size, line size and address width fixed, and double the associativity. What happens?

  1. index +1, offset same, tag −1
  2. index same, offset −1, tag +1
  3. index −1, offset same, tag +1
  4. index −1, offset +1, tag same

The same number of lines shared out two times as many per set gives half as many sets. One bit moves from index to tag.

D · LRU (fully associative)

D1

3 slots, LRU, sequence A, B, C, A, D, B, A, C. How many hits?

Write the order after every access (LRU first): A m [A] · B m [A B] · C m [A B C] · A hit [B C A] · D m, evicts B [C A D] · B m, evicts C [A D B] · A hit [D B A] · C m, evicts D. 2 hits.

D2

2 slots, LRU, sequence A, B, B, A, C, A, B, C. How many hits?

A m · B m [A B] · B hit [A B] · A hit [B A] · C m, evicts B [A C] · A hit [C A] · B m, evicts C [A B] · C m, evicts A. 3 hits.

E · Conflict misses

E1

The cache has 32 sets, is 2-way, and has 32-byte lines. An array is line-aligned and 6 lines bigger than the cache. It is read with stride 32, 50 times, LRU. Total misses?

The cache holds 64 lines, so the array has 70. Sets 0–5 each get 3 lines into 2 ways, so with LRU those 18 lines miss on every pass: 18 × 50 = 900. The other 26 sets hold 52 lines, and each misses once: 52. Total 952.

E2

Same cache, but the array exactly fills it (64 lines). Same 50 passes. Total misses?

Only cold misses: 64. Everything hits after the first pass.

E3

Back to the E1 array (70 lines), but now read with stride 16, so there are two accesses per line. Total misses over 50 passes?

The second access to each line comes right after the first, so it always hits, even in the thrashing sets. The misses are the same as in E1: 952. Only the number of accesses doubles (7000), so the hit rate goes up.

F · Coherence

F1

MESI. A line is in M in this cache, and another core reads it. New state?

  1. S, after a write-back
  2. I, after a write-back
  3. S, with no write-back
  4. M, with no change

The data is dirty, so it must be written back. In MESI, both copies can then be shared.

F2

Course MSI diagram. A line is in M in this cache, and another core reads it. New state?

  1. S, after a write-back
  2. I, after a write-back
  3. S, with no write-back
  4. M, with no change

In the course MSI, a remote R/W takes M to I. Only MESI goes to S here, so this is the trap.

F3

MESI. This core reads a line that no other cache holds. What state does the line get?

  1. S
  2. E
  3. M
  4. I

It's the only copy and it's clean, so E.

F4

The same core now writes to that line. What happens?

  1. E → M, after broadcasting an invalidate
  2. E → S, then S → M
  3. E → M, with no bus message
  4. It stays in E and sets the dirty bit

No other copy exists, so there is nothing to invalidate. This silent E → M is MESI's advantage over MSI.

G · Concepts

G1

A multicore chip runs a different program on each core. Its Flynn class is…

  1. SISD
  2. SIMD
  3. MISD
  4. MIMD

Many instruction streams, each working on its own data.

G2

A program reads a huge array once, from start to end. Which locality does it show?

  1. Temporal locality only
  2. Spatial locality only
  3. Both kinds of locality
  4. Neither kind of locality

Neighbouring elements are used one after another (spatial), but nothing is reused (no temporal).
