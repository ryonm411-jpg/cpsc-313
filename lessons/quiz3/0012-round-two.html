A · Writes: count the trips

Don't memorise a formula. List what physically happens, then add up the times. There are only four possible steps:

#StepWhen it happensCost
1Write the dirty victim back to the sourceWrite-back and a miss and the victim is dirtyd
2Fetch the line from the sourceA miss and write-allocated
3Write the data to the sourceWrite-through (every write, hit or miss); also a no-allocate missd
4Write the data into the cacheWhenever the line is in the cache at the endc, hidden if step 3 also happens (they run in parallel)
Three facts that kill the mistakes 1. Allocate = fetch. A write-allocate miss always pays one d to bring the line in. (Your A2 mistake.)
2. Only dirty victims cost. A clean victim is simply overwritten for free. Write-through caches never have dirty lines, so step 1 never happens for them. (Your A3 mistake.)
3. Write-through hides c; write-back always pays c. The cache write overlaps the slower source write, or stands alone.

Worked example, with c = 2 and d = 30:

CaseStepsTotal
WT, no-allocate, miss3d = 30
WT, allocate, miss2 (fetch) + 3 (write source, c hidden)2d = 60
WT, any hit3 (c hidden)d = 30
WB, allocate, miss, clean victim2 (fetch) + 4 (cache write)c + d = 32
WB, allocate, miss, dirty victim1 (write back) + 2 (fetch) + 4c + 2d = 62
WB, any hit4c = 2

Round two, with new numbers: c = 3, d = 40

Before you type an answer, write the step numbers down, for example “2 + 4”.

A·1. Write-through, write-allocate. A write miss?

Steps 2 + 3: fetch (40) + write source (40), with the cache write hidden. 2d = 80.

A·2. Write-back, write-allocate. A write miss that evicts a clean line?

Steps 2 + 4: fetch (40) + cache write (3) = 43. The clean victim costs nothing.

A·3. Write-back, write-allocate. A write miss that evicts a dirty line?

Steps 1 + 2 + 4: write back (40) + fetch (40) + cache write (3) = 83.

A·4. Write-through, no-write-allocate. A write miss?

Step 3 only: 40. Nothing enters the cache.

A·5. Write-through, write-allocate. A write hit?

Step 3, with c hidden: 40. Write-through hits are slow, which is why write-back exists.

A·6 (trap). Write-through, write-allocate. A write miss whose victim line was written to many times earlier. Latency?

Still 80. Under write-through every write already went to the source, so the victim is clean. Write-through never pays step 1.

A·7. Write-back, write-allocate. A write hit to a line that is already dirty?

Step 4 only: 3. Dirty or clean doesn't matter on a hit; the dirty bit just stays set.

A·8. Write-back, write-allocate, c = 3, d = 40. 95% of writes hit. 20% of misses evict a dirty line. Average write time? (2 decimals)

Average miss = 0.8 × 43 + 0.2 × 83 = 34.4 + 16.6 = 51.
Average = 0.95 × 3 + 0.05 × 51 = 2.85 + 2.55 = 5.40.

A·9. Write-through, write-allocate, d = 40. 90% of writes hit. Average write time?

Hit = 40, miss = 80. 0.9 × 40 + 0.1 × 80 = 36 + 8 = 44.

A·10. Write-back, write-allocate: hit 2, clean miss 42. Write-through, no-allocate: every write 10. All evictions clean. Break-even hit rate? (2 decimals)

2h + 42(1 − h) = 10, so 42 − 40h = 10, 40h = 32 and h = 0.80. Above 0.80, write-back wins.

A·11. Which step does a write-through cache never perform?

  1. Fetch a line from the source
  2. Write data to the source
  3. Write back a dirty victim
  4. Write data into the cache

Write-through has no dirty bit, so its lines are always clean.

A·12. Write-back, write-allocate. Which events make a write slower than c + d?

  1. A hit on a dirty line
  2. A miss that evicts a dirty line
  3. A miss that evicts a clean line
  4. A hit on a clean line

Only the dirty victim adds the extra d. Hits cost c no matter what.

E · Conflict misses: the set table

On the mock you made every line miss on every pass. That only happens to lines in sets that overflow. Every other set behaves as if the array fitted.

  1. Count lines. Cache lines = sets × ways. Array lines = array bytes ÷ line size. Extra = array lines − cache lines.
  2. Place the extras. Line n goes to set n mod sets. The extra lines land in sets 0, 1, …, extra − 1, which gives those sets one more line than they have ways.
  3. Each set on its own:
    • lines in set ≤ ways: each line misses once (a cold miss), then always hits.
    • lines in set > ways, with LRU and the same cyclic order: every line in that set misses on every pass, because LRU always evicts the line that comes next.
  4. Total = (overflow-set lines × passes) + (all other lines × 1).
  5. Stride smaller than a line? The other accesses in a line come right after its miss, so they hit. The misses don't change; only the number of accesses grows.
Worked example: E1 from Lesson 10 32 sets × 2 ways = 64 lines. The array has 70 lines, so 6 extra land in sets 0–5.
Sets 0–5 hold 3 lines each in 2 ways and overflow: 6 × 3 = 18 lines × 50 passes = 900.
Sets 6–31: 26 × 2 = 52 lines, each missing once = 52.
Total = 952. Not 70 × 50 = 3500: that is the “everything thrashes” mistake.

Round two: 16 sets, 4-way, 64-byte lines, LRU, line-aligned array, 100 passes

E·1. How many lines does the cache hold?

16 × 4 = 64.

E·2. The array is 68 lines, read with stride 64. Which set does the last line go into?

The last line is number 67, and 67 mod 16 = 3. The 4 extras are lines 64–67, in sets 0–3.

E·3. Same array, 100 passes. Total misses?

Sets 0–3 have 5 lines in 4 ways: 4 × 5 = 20 lines × 100 = 2000.
Sets 4–15: 12 × 4 = 48 lines, once each = 48.
Total 2048.

E·4. Same array, now stride 16 (4 accesses per line). Hit rate over 100 passes? (4 decimals)

The misses stay at 2048. Accesses = 68 × 4 × 100 = 27200. Hit rate = 1 − 2048/27200 = 0.9247.

E·5. The array is exactly 64 lines. Total misses over 100 passes?

Every set holds exactly 4 lines in 4 ways, so there are only cold misses: 64.

E·6. The array is 80 lines. Total misses over 100 passes?

16 extras, so every set gets 5 lines in 4 ways. Every set overflows: 80 × 100 = 8000. This is the only case where “everything misses every pass” is correct.

E·7. Back to 68 lines, but the cache is direct-mapped with 64 sets (same size). Total misses over 100 passes?

Sets 0–3 each get 2 lines in 1 way: 8 lines × 100 = 800. The other 60 lines miss once: 60. Total 860.

E·8. 68 lines again, but the cache is fully associative with 64 lines, LRU. Total misses over 100 passes?

There is one set, and it overflows, so every line misses on every pass: 68 × 100 = 6800.

E·9. Looking at E·3, E·7 and E·8: for an array slightly bigger than the cache, read cyclically with LRU, more associativity…

  1. makes the misses go up
  2. makes the misses go down
  3. leaves the misses the same
  4. depends on the stride

860 → 2048 → 6800. More ways means more lines share each overflowing set, and all of them thrash together. It's the opposite of the usual intuition, which is exactly why it gets asked.

F · Coherence: four rules

Ask two questions for every event: who did it (me or another core), and does anyone else hold the line?

EventMeEveryone elseBus message?
I read, missMESI: E if nobody else has it, otherwise S
MSI: always S		MESI: an M or E copy drops to S. Course MSI: an M copy goes to I. An M copy always writes back first.yes (read request)
I writeMAll go to IFrom S or I: yes (invalidate). From E or M: no
Another core readsM → write back, then MESI S, course MSI I
E → S · S → S · I → I
Another core writesAnything → I (M writes back first)
The only three things that differ between MSI and MESI 1. A read miss with no other copy: MSI gives S, MESI gives E.
2. A write to that line afterwards: MSI must invalidate (S → M), MESI is silent (E → M).
3. A remote read of an M line: course MSI gives I, MESI gives S. Both write back.

G · Concepts: two tests

Flynn: count the streams

Instruction streams = how many independent programs (program counters) run at once. Data streams = how many pieces of data one instruction works on.

Single dataMultiple data
Single instructionSISD: an old single-core CPUSIMD: one instruction on many values (vector, AVX, GPU)
Multiple instructionMISD: rare, you won't need an exampleMIMD: multicore, multiprocessor, distributed

G·1. One AVX instruction adds 8 pairs of floats at once. Flynn class?

  1. SISD
  2. SIMD
  3. MISD
  4. MIMD

One instruction, 8 data items.

G·2. A 16-core server runs a web server on some cores and a database on others. Flynn class?

  1. SISD
  2. SIMD
  3. MISD
  4. MIMD

Each core has its own program counter and its own data.

G·3. A GPU applies the same shading instruction to millions of pixels. Flynn class?

  1. SISD
  2. SIMD
  3. MISD
  4. MIMD

The same instruction across many data items is the SIMD idea.

G·4. A single-core, non-vector CPU running one program. Flynn class?

  1. SISD
  2. SIMD
  3. MISD
  4. MIMD

One stream of instructions, each on one piece of data.

G·5. A cluster of 100 machines connected by a network. Flynn class?

  1. SISD
  2. SIMD
  3. MISD
  4. MIMD

Many independent programs on many data. Distributed is still MIMD; it just doesn't share memory.

Locality: ask two yes/no questions

The test Temporal: is the same address used again soon? (reuse)
Spatial: is a nearby address (in the same line) used soon? (neighbours)
Answer each one separately. Two yeses = both; two noes = neither.

G·6. A small 1 KB array is summed 1000 times in a loop. The array accesses show…

  1. Temporal locality only
  2. Spatial locality only
  3. Both kinds of locality
  4. Neither kind of locality

Neighbours are used in a row (spatial), and each element comes back every pass (temporal).

G·7. The loop variable sum in for (...) sum += a[i]; shows…

  1. Temporal locality only
  2. Spatial locality only
  3. Both kinds of locality
  4. Neither kind of locality

It's one address, used on every iteration. There are no neighbours involved.

G·8. A linked list whose nodes are scattered randomly through memory is walked once. The node accesses show…

  1. Temporal locality only
  2. Spatial locality only
  3. Both kinds of locality
  4. Neither kind of locality

No reuse (once), and the next node is far away (not in the same line).

G·9. One column of a huge 2D double array is read once, with rows 8000 bytes long and 64-byte lines. The accesses show…

  1. Temporal locality only
  2. Spatial locality only
  3. Both kinds of locality
  4. Neither kind of locality

The stride is 8000 bytes, much bigger than a line, so there's no neighbour use, and nothing is reused.

G·10. The instruction fetches for a tight loop that runs 1000 times show…

  1. Temporal locality only
  2. Spatial locality only
  3. Both kinds of locality
  4. Neither kind of locality

Instructions sit one after another (spatial), and the loop body is fetched again on every iteration (temporal).
