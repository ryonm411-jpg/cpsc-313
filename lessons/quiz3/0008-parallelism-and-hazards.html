Parallelism & Hazard Review

Pipelining is one way to do many things at once. Here is where it sits among the others.

Your win for today: place any form of parallelism on the map, and count stalls under each mitigation (R3.2). About 15 minutes.

1 · The map

FormWhat it does
PipeliningOverlaps the stages of different instructions in one core
SuperscalarIssues more than one instruction per cycle, using multiple functional units
Out-of-orderReorders instructions and renames registers; a scheduler dispatches when operands are ready
HyperthreadingN copies of the registers share one core's logic; switches in hardware while waiting on memory
Multicore / multiprocessorSeveral full execution units, each with its own instruction stream (MIMD)
Vector / GPUOne instruction applied to many values (SIMD), such as Intel AVX
AcceleratorsNPU, crypto and compression units, FPGA: specialised hardware
DistributedMany machines over a network; no shared memory; each has its own OS
MultitaskingMostly an illusion: the OS rapidly switches between jobs

Flynn's taxonomy crosses single or multiple instruction streams with single or multiple data streams: SISD is a conventional uniprocessor, SIMD is vector, MISD is uncommon, MIMD is multicore. Slides 2.6

Which has multiple register sets sharing one core's execution logic?

  1. Superscalar execution
  2. Hyperthreading
  3. Multicore
  4. SIMD execution

Each hyperthread has its own registers, and the core switches to another while one waits on memory.

Which is true of a distributed system but not of multicore?

  1. Runs many threads at once
  2. Uses multiple processors
  3. Cores share no memory
  4. Has a cache at each level

Machines communicate over a network, each with its own OS.

Running 4 threads on 1 core with no hardware support is…

  1. True MIMD parallel work
  2. Multitasking by the OS
  3. SIMD on four data items
  4. Superscalar execution

They take turns, so it only looks simultaneous.

What limits how far pipelining and clock speed can go? (slides 2.6)

  1. Heat, skew and depth
  2. Hit rate and line size
  3. Tag bits and index bits
  4. Amdahl and Belady laws

Clock frequency is limited by pipeline depth, heat and clock skew. CPI is limited by the amount of instruction-level parallelism.

2 · Hazards are still on the quiz

R3.2 asks for best-case stalls. The “best case” assumes correct prediction. This applies to the standard 5-stage pipeline:

SituationStalling only+ forwarding+ prediction (best case)
ALU result used by the next instruction300
Load used by the next instruction311
Conditional jump220
ret333

irmovq $1, %rax then addq %rax, %rbx, stalling only. Stalls?

The result is not yet readable from the register file: 3 stalls with distance 1.

mrmovq 0(%rax), %rbx, then addq %rcx, %rdx, then addq %rbx, %rsi, with forwarding. Stalls?

The instruction in between means the loaded value is available from m_valM by the time the consumer is in Decode. Only a directly following consumer costs a stall.

Which instruction is never helped by forwarding or by prediction?

  1. mrmovq
  2. jXX
  3. ret
  4. addq

The return address is read from memory, so it is known too late to predict with what we have. It always costs 3.
