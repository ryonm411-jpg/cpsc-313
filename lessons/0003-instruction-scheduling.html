Instruction Scheduling

Same instructions, same answer, fewer bubbles. You just change the order.

Your win for today: take a straight-line block of y86, reorder it so it gives the same result with the fewest bubbles, and know when reordering stops mattering. That's the “Shuffling instructions” part of Tutorial 4. It's also the cheapest trick you'll use in Lab 5. About 15 minutes.

Warm-up: recall from Lessons 1–2

With no forwarding, how many stall cycles does subq wait?

addq %rax, %rbx
nop
subq %rbx, %rcx
  1. 0 stalls
  2. 1 stall
  3. 2 stalls
  4. 3 stalls

Distance 2 → 2 stalls. Without forwarding, the consumer's Decode has to happen after the producer's Write-back, so distance 1/2/3 cost 3/2/1 stalls. Distance 4 or more costs 0. Lesson 1.

1 · Count first

The program from the tutorial. The letters are just names. Each line is a single instruction.

A. irmovq 0x123, %rax
B. irmovq 0x456, %rbx
C. addq   %rax, %rbx
D. irmovq 0x789, %rsi

G. modq   %rsi, %rax
H. divq   %rbx, %rdi

Q1. On the unpipelined (sequential, SEQ) y86 processor, how many bubbles does it produce?

0. SEQ runs each instruction through all five stages before starting the next one. By the time C starts, A and B are completely done. Nothing overlaps, so there's nothing to wait for. You pay for this with a long clock cycle instead CS:APP §4.3–4.4.

Q2. Pipelined, no forwarding. How many bubbles in the original order?

8 = 3 + 3 + 2. C needs %rbx from B at distance 1 → 3. F needs %rdi from E at distance 1 → 3. H needs %rdi from F at distance 2 (G sits between) → 2. G is free: %rsi (D) and %rax (A) are both far enough back, especially since F's stall gave them extra time. Every other dependency is already 4 or more apart.

2 · What makes a reorder legal?

You may move an instruction past another unless the two touch the same register in a way where order matters CS:APP §4.5.5:

PairRuleExample here
write → reada reader stays after the writer it needs. This is the real data dependency, the one that causes hazards.A, B → C
read → writea writer stays after earlier readers of the old value, or they'd see the new oneC reads %rax, then G overwrites it → G after C
write → writethe last writer stays last, so the final value is right(none here)

Condition codes act like one more register. Every OPq writes them, and jXX/cmovXX read them. Here H sets the final condition codes. If H is no longer last, the registers still match but the codes don't. That only matters if a later jump or cmov reads them.

Which instructions must come after C? (select all)

  1. A
  2. B
  3. F
  4. G
  5. H

G (it overwrites the %rax that C reads) and H (it reads the %rbx that C writes). F belongs to the other chain, so it can go anywhere relative to C. That freedom is what you use to fill gaps.

3 · The scheduling idea

Without forwarding, a reader is free once there are at least 4 instruction slots (cycles, really) between it and its writer. So start the writers early, and fill the gaps with independent work. Two independent chains are perfect for this. While one chain waits on its writer, the other chain gets work done.

Try it. Type an order (like BACDEFGH) and press Run. The widget checks that your result still matches the original and draws the pipeline. Find the fewest bubbles you can before peeking at the minimum.

Q3. What's the fewest bubbles a legal order can produce (no forwarding)?

4. For example, ABDECFGH: all four irmovqs go first. C is 1 short of the 4-slot gap from B (1 bubble). F rides on that delay but is still 1 short (1 bubble). H follows F at distance 2 (2 bubbles). 26 different legal orders all tie at 4. You can't get to 0 because the chain irmovq → add → div needs two 4-slot gaps, and with only eight instructions there isn't enough independent work to fill both.

Q4. Your best order, now with forwarding. How many bubbles?

0. And the original order also gets 0. With forwarding, every ALU result (irmovq, addq, modq, divq) reaches the next instruction through e_valE with no wait. Only a load/use (a value from mrmovq or popq, used by the very next instruction) still costs a bubble. This program has no loads, so there's nothing left to schedule. Tick “forwarding” above to see it.

What this means for Lab 5 The pipeline you'll optimize has forwarding. So scheduling comes down to one rule: never use a loaded value in the very next instruction. Put any independent instruction between them (a pointer increment, a constant, the other half of a swap). Each such slot you fill saves 1 cycle every time that code runs, and in a sort's inner loop that adds up.

With forwarding, which pair costs a bubble?

  1. addq %r8, %r9 then subq %r9, %r10
  2. popq %r9 then subq %r9, %r10
  3. irmovq $8, %r9 then subq %r9, %r10
  4. rrmovq %r8, %r9 then subq %r9, %r10

popq gets %r9 from memory (valM, end of Memory). That's a load/use, so 1 bubble, then m_valM. The other three produce valE, which is forwarded from e_valE for free.
