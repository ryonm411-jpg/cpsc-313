Value Forwarding

Two questions answer every forwarding problem: when do I need it? and when does it exist?

Your win for today: given any producer → consumer pair, name the exact signal the value is forwarded from (e_valE, M_valE, W_valE, m_valM, W_valM) and how many stall cycles remain. That's precisely what in-class questions I9.1 and I9.3 ask. About 15 minutes.

Warm-up: recall from last lecture

No forwarding, stalling only. How many cycles does subq stall?

addq %rax, %rbx
subq %rbx, %rcx
  1. 0 cycles
  2. 1 cycle
  3. 2 cycles
  4. 3 cycles

subq sits in Decode until addq has written %rbx in Write-back. The register file only shows the new value the following cycle, so subq spends 4 cycles in D (F D D D D E): 3 stalls. Slides 2.3, “Recall stalling”.

Three wasted cycles for the most common pattern in all of code: compute something, then use it. Forwarding fixes this.

1 · Need vs. have

The slides ask two questions slides 2.3, “Forwarding (1)/(2)”:

  1. When does subq NEED %rbx? By the end of its Decode stage, because Execute starts next cycle and the ALU needs its operands then.
  2. When does addq HAVE %rbx? At the end of its Execute stage. The ALU just produced it. That signal is called e_valE.

Those happen in the same cycle. addq is in E while subq is in D. So we add a wire from the ALU output back into Decode's operand-select logic (the slide's “Forward A / Forward B” boxes). No stall.

The core idea The value already exists somewhere in the pipeline. It just hasn't reached the register file yet. Forwarding takes it from wherever it currently is and delivers it to Decode.

2 · Reading the signal names

The names follow a strict convention from CS:APP Bryant & O’Hallaron, CS:APP 3e §4.5.3:

PrefixMeansExample
lowercase e_, m_a signal computed this cycle by that stage's logic (its output)e_valE = ALU output right now · m_valM = data-memory output right now
UPPERCASE M_, W_a value stored in that pipeline register (computed by an earlier stage, last cycle or before)M_valE = the ALU result of the instruction now in Memory · W_valM = loaded value of the instruction now in Write-back

And the suffix tells you which kind of value:

  • valE: the ALU result (OPq, irmovq, rrmovq/cmovXX, and the new %rsp from push/pop/call/ret). It first exists at the end of Execute.
  • valM: a value read from memory (mrmovq, and the register target of popq). It first exists at the end of Memory.

Why is there no m_valE in the forwarding logic? The Memory stage doesn't change valE. It just passes it along, so the value sitting in the M register (M_valE) is the one to use. m_valE is a distractor in I9.3.

3 · The distance rule

Count the distance: how many instructions later the consumer comes (back-to-back = 1; one instruction between = 2). While the consumer is in Decode, the producer is distance stages ahead:

DistanceProducer is in…ALU result (valE)Loaded value (valM)No forwarding: stalls
1Executee_valE · 0 stalls1 stall, then m_valM3
2MemoryM_valEm_valM2
3Write-backW_valEW_valM1
4+doneregister file (no forwarding needed)0

Careful: nops count toward distance. So does any unrelated instruction between producer and consumer.

Above: one producer feeding consumers at distance 1, 2 and 3, with forwarding. No stalls. Each consumer grabs %rbx from a different place.

4 · The one case forwarding can't fix: load/use

Swap the addq for a load:

mrmovq 0(%rax), %rbx
addq   %rbx, %rcx

The loaded value first exists at the end of Memory. But addq needs it at the end of Decode, which is the same cycle mrmovq is still in Execute. The value doesn't exist yet. A wire can't send it back in time. So the hardware stalls addq one cycle, then forwards m_valM CS:APP §4.5.5, “Load/use data hazards”.

Exam phrasing trap If a question asks how to make a back-to-back load/use run “without stalling”, the answer is “forwarding is needed, but it's not possible to forward a value that will make this work.” If it asks “with stalling and forwarding”, the answer is 1 stall + m_valM.

5 · Check yourself

Slide 2.3, “Hey, Quick Q”. Where is %rbx when subq needs it?

addq   %rax, %rbx
irmovq 10, %rdx
subq   %rbx, %rcx
  1. e_valE
  2. M_valE
  3. W_valE
  4. m_valM

Distance 2. subq still needs the value at the end of its Decode (same spot as before). But addq is now one stage further along, in Memory, so the value sits in the M pipeline register: M_valE.

The slides list three ideas that don't work. Why can't we just forward e_valE to the start of the Execute stage?

  1. The ALU result is too wide to forward
  2. Execute has no input port for it
  3. It feeds an instruction its own output
  4. The register file would be overwritten

Feeding e_valE into the start of Execute delivers the value to the same instruction that produced it. That creates a combinational loop. The other two failures: writing e_valE into the register file (only readable next cycle, too late), and forwarding M_valE to the new logic (it's in the M register only next cycle).

With forwarding: how many stall cycles, and from where?

popq   %rbx
nop
rrmovq %rbx, %rdx
  1. 0 stalls, m_valM
  2. 0 stalls, M_valE
  3. 1 stall, m_valM
  4. 1 stall, W_valM

popq loads %rbx from memory, so it's a valM value. Distance 2 means popq is in Memory exactly when rrmovq is in Decode, and the memory output m_valM is ready by the end of that cycle. No stall. (M_valE would be the new %rsp, which is a different register.)

6 · Practice until it's boring

Endless randomly generated problems. The simulator checks you and draws the pipeline diagram. Do at least 8 in a row correct. Answer before you look anything up; the effort of recalling is what makes it stick.

Why this matters

Early RISC chips had no stalling and no forwarding. The compiler, or a human writing assembly, had to insert nops by hand. Today the hardware handles it slides 2.3, “Wrapping Up”. You're learning what that hardware has to work out every cycle.
