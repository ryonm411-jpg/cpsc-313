Directories, Paths and Links

A directory is a file full of (name, inode number) pairs. Once you know that, path lookups and links follow.

Your win for today: count the disk reads for a path (R4.13), say which ln commands work (R4.14), match the vocabulary (R4.15), and redo the MSI/MESI comparison (R4.2, R4.3). About 25 minutes.

1 · Directories

A directory is a file whose contents are directory entries. Each entry maps a name → inode number. Programs can read a directory but only the file system writes it, which keeps the structure valid. Every directory has . (itself) and .. (its parent). OSTEP ch. 39 §39.12–39.14; ch. 40 §40.4

directory "home" (inode 12), its data block:
  name     inode #
  .        12
  ..       2
  notes    57
  src      90
Three words that sound alike (R4.15) inode: on-disk metadata of one file, including the LBN → PBN map.
directory entry: one name → inode number mapping.
directory: a file whose contents are directory entries, written only by the file system.
v-node: the in-memory kernel copy of a file's metadata (Lesson 2's third table).

Where is a file's name stored?

  1. In the file's inode
  2. In a directory entry
  3. In the open-file table
  4. In the file's first block

The inode knows nothing about names. That's what lets one file have several names (hard links).

2 · Resolving a path (R4.13)

To open /l/brd/n/w/gn/y, the file system walks one component at a time. The root's inode number is fixed and known.

  1. Read /'s inode, then /'s data block. Find "l" → inode #.
  2. Read l's inode, then l's data block. Find "brd".
  3. Repeat for brd, n, w, gn: 2 reads each.
  4. Read y's inode, then y's first data block, which holds the first byte.
Rule With k names after the root, nothing cached, one-block directories and one inode per block:
reads = 2 × (k + 1) (every directory including /, plus the file, each costs inode + one data block).
/l/brd/n/w/gn/y: k = 6, so 14.

Variations to watch for: if the root inode is already cached, subtract 1. If a directory spans 2 blocks, the name might be in the second one. If the question asks only to open the file (not read a byte), drop the last data block.

R4.14: ln ../ myParentDir fails (hard link to a directory). ln -s ../fooFile barFile works. ln -s /Volumes/OtherFilesystem/a newfile works (symbolic links may cross file systems). The answer is the second and third.

Which command fails?

  1. ln -s /Volumes/OtherFilesystem/dirA myDir
  2. ln ../fooFile barFile
  3. ln /Volumes/OtherFilesystem/fileA newfile
  4. ln -s ../ upDir

A hard link across file systems fails, because the inode number would refer to the wrong disk. The other three: symlink to a dir, hard link to a file on the same FS, symlink to a dir.

ln a b, then rm a. What happens to the data?

  1. Still readable through b
  2. Deleted; b is dangling
  3. Moved into b's own inode
  4. Lost until a is recreated

Both names pointed to the same inode. rm drops the link count from 2 to 1; blocks are freed only at 0.

4 · Back to coherence: MSI vs MESI (R4.2, R4.3)

Recap from Quiz 3, Lesson 7:

Pairs (R4.2) Same cache slot (set #22): the two caches may hold different lines there, so every pair is possible, including E/E and E/M.
Same memory line: M and E mean "only I have it", so the only legal pairs are I + anything and S + S. From R4.2's second list: (a) I/E, (c) S/S, (d) I/I.
Where the protocols differ (R4.3) Same start state (so I, S or M; MSI has no E):
• Core 1 read miss (start I, nobody else has it): MSI → S, MESI → E. Different.
• Core 2 reads while Core 1 is in M: course MSI → I, MESI → S. Different.
• Core 1 read hit: no change in either. Core 1 write hit: M in both.
So R4.3's answer is the read miss and "Core 2 reads".

Same memory line, two MESI caches. Which pair is possible?

  1. E and S
  2. M and S
  3. E and E
  4. I and M

Exclusive states pair only with I.
