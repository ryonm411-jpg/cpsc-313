Course conventions used here (from your PrairieLearn questions): if nothing has been read yet, reading the inode counts as an IO. A multi-level tree uses only as many levels as the file needs. A · Disks (R4.6, R4.7)

1 · The average seek is 4 ms, the disk spins at 7,200 RPM, and there are 500 sectors per track. What is the average time to read one sector, in ms (2 decimals)?

Rotation = 60,000 ÷ 7,200 = 8.333 ms. Half of that is 4.167, and one sector's transfer is 8.333 ÷ 500 = 0.017. Total: 4 + 4.167 + 0.017 = 8.18 ms.

2 · A new disk spins slower, with the same arm and the same sectors per track. Which statements are true? (Pick all that apply.)

  1. The seek time stays the same
  2. The rotational latency grows
  3. The transfer time per sector shrinks
  4. The throughput gets higher

Seek time depends on the arm, so it doesn't change. A slower spin makes each rotation longer, which increases the rotational latency and the transfer time, and lowers the throughput.

3 · Seek 8 ms, 6,000 RPM, 250 sectors per track. A 50-sector file sits in consecutive sectors on one track. How long does it take to read the whole file, in ms?

Rotation = 10 ms. You pay the seek and the rotational wait once: 8 + 5. Then 50 sectors × 0.04 = 2. Total: 15 ms.

4 · Same disk and same file, but now every sector is in a random place. How long does it take, in ms?

Each sector pays the seek and the rotational wait again: 50 × (8 + 5 + 0.04) = 652 ms, about 43 times slower. That gap is why ext2 tries to keep files contiguous.

B · System calls and file descriptors (R4.4, R4.5, I22)

5 · Which pair of lines implements prog > out.txt?

  1. fd = open("out.txt", O_RDONLY); dup2(fd, 0);
  2. fd = open("out.txt", O_WRONLY|O_CREAT); dup2(1, fd);
  3. fd = open("out.txt", O_WRONLY|O_CREAT); dup2(fd, 1);
  4. fd = open("out.txt", O_RDONLY); dup2(fd, 1);

Output means fd 1, and the file has to be opened for writing. dup2(fd, 1) copies fd into slot 1. Option 2 has the arguments reversed.

6 · A file is 2,000 bytes long. lseek(fd, 300, SEEK_SET); read(fd, buf, 1000); lseek(fd, -100, SEEK_END); x = read(fd, buf, 500); What is x?

SEEK_END − 100 puts the offset at 1,900. Only 100 bytes are left, so this is a short read: x = 100.

7 · fd1 = open(f); dup2(fd1, 9); read(fd1, buf, 640); read(9, buf, 215); What does lseek(fd1, 0, SEEK_CUR) return?

dup2 makes fd 9 share fd1's entry, so both reads move the same offset: 640 + 215 = 855.

8 · fd1 = open(f); fd2 = open(f); write(fd1, 300 × 'a'); write(fd1, "Q", 1); read(fd2, buf, 300); read(fd2, &c, 1); What is c?

  1. a
  2. not enough info
  3. Q
  4. a zero byte

The two opens have separate offsets. fd2 starts at 0, skips bytes 0–299 (the a's), and reads byte 300. Both fds see the same file data, so that byte is Q.

9 · Two threads in the same process share fd 3. Thread 1 reads 100 bytes and thread 2 then reads 50. What is fd 3's offset now?

Threads share the process's fd table, so they share the open-file entry and its offset: 150. (Slides 4.2.)

10 · A process opens a file once and forks. The child calls dup() on that fd, and then the parent calls close() on its own copy. What is the open-file entry's reference count?

After open, fork and dup, three fds point at the entry: 3. The parent's close brings it down to 2.

11 · 0–2 are open. close(0); a = open("in.txt", O_RDONLY); What is a?

0 is now the lowest free number, so a = 0. This is the older way of redirecting input, done without dup2.

C · Index structures (I24, Lab 8, R4.8–R4.12)

For this section, nothing about the file has been read yet unless a question says otherwise.

12 · Single extent, 4,096-byte blocks, maximum extent 900,000 blocks. How many IOs to read block 517,203?

Read the inode to get the extent's start, then read the data block at start + 517,203. That's 2 IOs. With a single extent the answer is always 2.

13 · Multi-level index (at most 3 levels), 4,096-byte blocks, 4-byte addresses. The file has 5,000 blocks. How many IOs to read block 4,321?

p = 1,024. 5,000 is more than 1,024, so one level isn't enough, but 1,024² is, so the file needs 2 levels. Inode + 2 index blocks + data = 4.

14 · Hybrid index: 2,048-byte blocks, 4-byte addresses, 10 direct, 1 indirect, 1 double, 1 triple. How many IOs to read LBN 600?

p = 512. The directs cover LBNs 0–9 and the indirect covers 10–521. LBN 600 is past that, so it's under the double: inode → double block → indirect block → data = 4.

15 · Flat index, 4,096-byte blocks, 8-byte addresses, and the index can be at most 100 blocks. What is the largest file, in KB?

p = 512. 100 index blocks × 512 = 51,200 data blocks, × 4 KB = 204,800 KB.

16 · Hybrid index, 1,024-byte blocks, 4-byte addresses, 12 direct, 1 indirect, 1 double, no triple. What is the largest file, in KB?

p = 256. (12 + 256 + 65,536) blocks × 1 KB = 65,804 KB.

17 · 2,048-byte blocks, 4-byte addresses, 8 direct pointers. What is the smallest byte offset that needs the double indirect block?

(8 + 512) × 2,048 = 1,064,960.

18 · Multi-level, p = 16, and the file needs 3 levels. LBN 1,000. What is the Level 2 position?

Write 1,000 in base 16: 1,000 = 3·256 + 14·16 + 8, so the positions are 3, 14, 8. Level 2 is 14.

19 · Hybrid, p = 1,024, 12 direct, then 1 indirect, 1 double, 1 triple. LBN 5,000. What is the double index?

5,000 − 12 = 4,988, which is at least 1,024. Subtract 1,024 to get 3,964, which is less than 1,024², so it's under the double. Double index = ⌊3,964 ÷ 1,024⌋ = 3.

20 · Same LBN. What is the indirect index?

3,964 mod 1,024 = 3,964 − 3,072 = 892. The metadata index is 13 and the triple is −1.

21 · Extents (start, length): (300, 4), (1020, 8), (64, 5). Which PBN holds LBN 13?

13 − 4 = 9, then 9 − 8 = 1. That lands in the third extent at offset 1: 64 + 1 = 65.

22 · In which structure does a 1-byte file still need the entire index allocated?

  1. Single extent
  2. Flat index
  3. Multi-level
  4. Hybrid index

A flat index is one fixed array that's sized for the largest possible file. Slides 4.4 give the example of a 1-byte file using 257 blocks.

23 · Which structure suffers most from external fragmentation and from files that grow?

  1. Single extent
  2. Flat index
  3. Multi-level
  4. Hybrid index

A single extent needs one contiguous run of free blocks. If the blocks right after the file are taken, it can't grow in place.

D · Naming, metadata and links (R4.13–R4.15, slides 4.5)

24 · Nothing is cached, every inode is in its own block, and each directory fits in one block. How many IOs does open("/x/y/z.dat", O_RDONLY) take?

/, x and y each cost their inode plus their data block: 6. Then z.dat's inode: 7. open() doesn't read the file's data. (Tutorial 9.)

25 · The program then reads z.dat's first byte. How many IOs in total, counting the open?

7 + 1 data block = 8. That's the same as the formula 2(k + 1) with k = 3.

26 · Which structure maps a file name to an inode number?

  1. the inode
  2. a dir entry
  3. a superblock
  4. a data bitmap

A directory entry is a (name, inode number) pair. The inode holds everything about the file except its name.

27 · touch f; ln f g; ln -s f h; ln g k; rm f. What is the link count of the inode that f used to name?

f, g and k are all hard links to the same inode, for a count of 3. The symlink h doesn't count. rm f leaves 2. h now dangles, because it stores the text "f".

28 · Directory d contains 4 subdirectories and 10 regular files. What is d's link count?

2 + 4 = 6. The 2 are d's entry in its parent and d's own .. Each subdirectory's .. adds 1. Files add nothing.

29 · What is the inode number of Heron?

  1. 0x71
  2. 0x6a
  3. 0x75
  4. 0x9c

Heron's entry starts at 0x5c with the bytes 75 00 00 00, which is 0x75. 0x71 is Otter's inode.

30 · What type is todo-list?

  1. DIR
  2. REG
  3. DEL
  4. LNK

Its entry is at 0x48: inode 0x80, reclen 0x14 = 20, type 0x0a = 10, which is a symbolic link. Its reclen is 20 because 8 + 9 + 1 = 18, rounded up to 20.

31 · Which name has inode 0x9c?

  1. Lynx
  2. Badger
  3. Otter
  4. Heron

The last entry is 0x9c, Badger. The earlier Badger at 0x28 has inode 0, so it's a deleted leftover. The same name can appear twice this way.

32 · How many valid entries does this directory have, counting . and ..?

There are 8 entries, and one of them (the first Badger) has inode 0, which leaves 7. Without . and .. it would be 5. Read the question to see which one it wants.

F · v6 and ext2 (I26, P24)

33 · Which file system can more easily allocate a file contiguously?

  1. ext2
  2. V6
  3. can't tell

ext2's bitmaps let it search for a run of free blocks, and its block groups keep data near the inode. v6's free list hands blocks out in nearly random order.

34 · v6, with the inode in memory and 512-byte blocks. A 20-block file is a "large" file, so its first 7 slots are single indirect pointers. How many IOs to read LBN 10?

One indirect block (2-byte addresses, so p = 256) covers LBNs 0–255. Read that indirect block, then the data block: 2.

35 · ext2 with 4,096-byte blocks and one block bitmap per group. How much data can one block group hold?

  1. 32 MB
  2. 4 MB
  3. 128 MB
  4. 1 GB

One bitmap block has 4,096 × 8 = 32,768 bits, which tracks 32,768 blocks. × 4 KB = 128 MB.

G · Coherence (R4.2, R4.3)

36 · Which events end in different states under the course's MSI and MESI diagrams? (Pick all that apply.)

  1. A read miss on a line nobody holds
  2. Core 2 reads Core 1's M line
  3. A core writes to its S line
  4. Every core is in state I

A read miss with no other copies gives S in MSI and E in MESI. A remote read of an M line goes M → I on the course MSI diagram and M → S in MESI. Writing to an S line goes to M and invalidates the others in both protocols.
