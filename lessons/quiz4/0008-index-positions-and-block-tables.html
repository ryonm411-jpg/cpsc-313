Walking an Index: Positions and Block Tables

Same idea as counting IOs, but now you name the exact slot you use at each step, and then follow real block numbers through a table.

Your win for today: fill in the "index at each level" boxes (L8-Ind.13, 14), and follow pointers through a block table to a physical address (I24.4, I24.5). About 25 minutes.

1 · It's just a number written in base p

Each index block has p slots, numbered 0 to p − 1. Going down one level picks one slot, exactly like reading one digit of a number written in base p.

Multi-level (L levels needed; Level 1 is the root) Level k position = ⌊LBN / pL − k⌋ mod p. The last level is just LBN mod p.
Levels the file doesn't need get −1.

Check against the course's example (p = 4, 3 levels, LBN 61): 61 in base 4 is 3 3 1, so the positions are 3, 3, 1.

L8-Ind.13, solved

8192-byte blocks, 4-byte addresses: p = 2048. The file is 2,048 blocks, so one level is enough (≤ p). LBN 1497 → Level 1 = 1497, Level 2 = −1, Level 3 = −1. This matches the course example's note that a file of 4 or fewer blocks has index blocks only at level 1.

p = 8, the file needs 2 levels. What is the Level 1 (root) position for LBN 45?

⌊45 / 8⌋ = 5 (and Level 2 = 45 mod 8 = 5 too). 45 in base 8 is 55.

2 · Hybrid positions

Metadata slots go in order: directs, then indirect(s), then double(s), then triple(s). Subtract each region's size until the LBN fits. Slides 4.4, slides 41–43; course example in L8-Ind.14

  1. LBN < d → metadata index = LBN. The rest are −1.
  2. r = LBN − d. If r < p → metadata index = d, indirect index = r.
  3. r −= p. If r < p² → metadata index = d + 1, double index = ⌊r / p⌋, indirect index = r mod p.
  4. r −= p². Triple: metadata index = d + 2, triple index = ⌊r / p²⌋, double index = ⌊(r mod p²) / p⌋, indirect index = r mod p.

L8-Ind.14, solved

p = 2048, 8 direct. LBN 3,587,025. Subtract 8 → 3,587,017, which is ≥ 2048. Subtract 2048 → 3,584,969, which is < 2048² = 4,194,304, so it's under the double (metadata index 9). Double index = ⌊3,584,969 / 2048⌋ = 1750. Indirect index = 3,584,969 − 1750 × 2048 = 969. Triple = −1.

Answers: metadata 9, indirect 969, double 1750, triple −1. Watch the box order: PrairieLearn asks for the indirect index before the double.

The course example: p = 4, 2 direct, 1 indirect, 1 double. Which positions does LBN 19 use?

  1. metadata 2, indirect 3, double 1
  2. metadata 3, indirect 3, double 1
  3. metadata 3, indirect 1, double 3
  4. metadata 2, indirect 1, double 3

19 − 2 − 4 = 13. Double slot (metadata 3), double index ⌊13/4⌋ = 3, indirect index 13 mod 4 = 1.

3 · Following pointers through a block table (I24.4, I24.5)

Now the slots hold real numbers. With 16-byte blocks and 2-byte addresses, each block holds 8 addresses, so each table row is a PBN followed by 8 numbers.

  1. Work out the positions first, as in §1 or §2.
  2. Find the row whose first number is the pointer you're following. Read the number at the position you need (counting from 0, not counting the row's own PBN).
  3. That number is the next block. Repeat until the last level, whose number is the answer.

I24.5, method

4 direct, 1 indirect, 1 double, p = 8, LBN 75: 75 − 4 − 8 = 63, so it's under the double indirect (26420). Double position ⌊63/8⌋ = 7, indirect position 63 mod 8 = 7. So: find row 26420, take its entry 7 → block X; find row X, take its entry 7 → the answer.

4 · Tutorial 9: when does each structure win?

The setup: hybrid with 5 direct, 1, 1, 1 vs. multi-level with 8 roots (trees of height up to 3), p = 2048. In the multi-level index, all 8 trees must be the same height.

Smallest file size (in blocks) where the hybrid uses more index blocks than the multi-level?

6 blocks: the hybrid needs its indirect block for the 6th, but the multi-level still uses 6 of its 8 direct roots. (Tutorial 9 solution.)

Example file size where the multi-level uses more index blocks than the hybrid?

2049: the multi-level needs two height-1 trees (2 index blocks), while the hybrid needs 5 direct + 1 indirect block. (Tutorial 9 solution.)
