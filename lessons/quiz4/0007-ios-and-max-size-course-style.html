Counting IOs and Maximum Sizes, the Course's Way

Your pasted I24 and Lab 8 questions follow two rules my earlier lessons didn't use. Learn those two and these questions turn into arithmetic.

Your win for today: answer any variant of I24.1–I24.3, I26.3 and L8-Ind.9–12 correctly. About 20 minutes.

1 · The two course rules

Rule 1: the inode counts When the question says "neither the file's metadata structure nor any other data or metadata for this file has been read yet", reading the inode is an IO.
IOs = 1 (inode) + index blocks on the way down + 1 (the data block).
If it says the inode is already in memory (I26.3), drop that 1.
Rule 2: a multi-level tree is only as deep as the file needs The inode holds the root pointer. A 1-block file: the root points straight at the data (0 index levels). Up to p blocks: one index block. Up to p² blocks: two levels. And so on. p = block size ÷ address size. Slides 4.4, "Multi-level Index (Tree)", slides 27–36

Lesson 3 counted reads "with the inode already in memory". These questions don't make that assumption, so every answer is one higher.

2 · Your questions, solved

I24.1: single extent

1024-byte blocks, max extent 233,332 blocks, read block 104,988. The inode stores the extent's start and length, so the data block is at start + 104,988. Read the inode, then the block: 2 IOs. The numbers are there to distract you; a single extent is always 2. Slides 4.3: "Random access needs 2 reads to get disk data (inode + data block)"

I24.2: multi-level

2048-byte blocks, 4-byte addresses: p = 512. The file has 512 blocks, which is ≤ 512, so one index block is enough. Inode → index block → data block = 3 IOs. The "maximum of 2 levels" is just an upper limit; this file doesn't need the second level.

I24.3: hybrid

4096-byte blocks, 8-byte addresses: p = 512. The 8 directs cover LBN 0–7. The indirect covers the next 512 (8–519). The double covers the next 512² = 262,144 (520–262,663). Block 145,592 is under the double, so: inode → double block → indirect block → data block = 4 IOs.

I26.3: v6 with the inode in memory

A 4-block v6 file uses direct pointers (v6 small files have 8). The inode is already in memory, so you only read the data block: 1 IO.

Multi-level, 1024-byte blocks, 4-byte addresses (at most 3 levels). The file has 1,000 blocks. Nothing has been read. IOs to read block 999?

p = 256. 1,000 > 256, so one level isn't enough; 256² = 65,536 ≥ 1,000, so it takes 2 levels. Inode + 2 index blocks + data = 4.

Hybrid, 12 direct pointers, nothing read yet. IOs to read block 5?

Block 5 is direct: inode + data = 2.

3 · Maximum file size in KB (L8-Ind.9–12)

Count the data blocks the structure can reach, then multiply by the block size in KB (block size ÷ 1024).

StructureData blocks reachableYour Lab 8 question
Single extentmax extent length380,980 × 1 KB = 380,980 KB
Flat index of k index blocksk × pp = 2048, so 2,754 × 2,048 × 8 KB = 45,121,536 KB
Multi-level, r roots, L levelsr × pLp = 1024, so 1 × 1024² × 4 KB = 4,194,304 KB
Hybridd + s·p + dd·p² + t·p³p = 512, so (6 + 2·512 + 512² + 512³) × 2 KB = 268,961,804 KB
Traps For the flat index, "maximum index size of 2,754 blocks" is the size of the index, not of the file. Each index block holds p addresses, so multiply by p. This matches the slides' example: 4 KB blocks with a 1 GB maximum need a 256-block index. Slides 4.4, slides 19–23
For the hybrid, count every indirect pointer. L8-Ind.12 has 2 singles, so it's 2·p.
For the extent, the address size doesn't matter.

Flat index, 1024-byte blocks, 4-byte addresses, index of 4 blocks. Max file size in KB?

p = 256. 4 × 256 = 1,024 data blocks × 1 KB = 1,024 KB.
