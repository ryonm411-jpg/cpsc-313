Mock Quiz 4

Every Quiz 4 goal covered so far, mixed together, with fresh numbers.

How to take it Set a 50-minute timer. Use only paper, a calculator, the MESI diagram and the man pages (man 2 open, man 2 dup, man 2 fork). Keep the lessons and the cheat sheet closed. Each answer is marked as soon as you give it, so write your reasoning first. This is my own practice set, not a copy of the real quiz. A · Disks

1 · Access time

Average seek 6 ms, 10,000 RPM, 200 sectors per track. What is the average time to read one sector, in ms? (2 decimals)

Rotation = 60,000 / 10,000 = 6 ms. Half a rotation = 3. Transfer = 6 / 200 = 0.03. Total 6 + 3 + 0.03 = 9.03. Lesson 1 §3

2 · Rotation

A disk spins at 5400 RPM. Average rotational latency, in ms? (2 decimals)

60,000 / 5400 = 11.111 ms per rotation. On average you wait half: 5.56.

3 · What changes

A new disk packs more sectors onto each track and keeps the same RPM and arm. What happens to the time to transfer one sector?

  1. It gets larger
  2. It stays the same
  3. It gets smaller
  4. Not enough information

Transfer = rotation ÷ sectors per track. Same rotation, more sectors, so each one passes under the head faster. Seek and rotational latency don't change.

4 · Block devices

Why does the OS read whole blocks from a disk instead of single bytes?

  1. Bytes on disk aren't addressable at all
  2. Getting there costs far more than reading
  3. Blocks are compressed when stored
  4. The CPU can only load 4 KB at a time

Seek and rotation are milliseconds, and the transfer itself is tiny. Once you've paid to get there, you take a whole block. The disk also only reads whole sectors.

B · File descriptors

5 · Two opens

The file holds abcdef. Processes A and B each call open() on it. A reads 2 bytes, then B reads 1 byte. What does B read?

  1. a
  2. b
  3. c
  4. d

Two separate open() calls make two open-file-table entries, each with its own offset. B's offset is still 0. Lesson 2

6 · fork

Same file. A process opens it, reads 2 bytes, then calls fork(). The child reads 1 byte. What does the child read?

  1. a
  2. b
  3. c
  4. d

fork copies the fd table, but both copies point at the same open-file entry, so they share one offset, which is already 2.

7 · Lowest free fd

A process starts with only fds 0, 1 and 2 open. It runs x = open(…); y = open(…); close(x); z = open(…); w = dup(y);. What is w?

open and dup return the lowest free fd. x = 3, y = 4. close(3) frees 3, so z = 3. dup(4) gets the lowest free one, 5.

8 · Reference count

A process opens a file once, then calls fork(). The child then calls dup() on that fd. What is the reference count of the open-file-table entry?

open: 1. fork copies the fd, so 2. dup adds another fd pointing at the same entry: 3. There's still only one entry and one offset.

9 · Redirection

You want cmd >> log.txt. Which pair of lines sets it up?

  1. fd = open("log.txt", O_RDONLY); dup2(fd, 0);
  2. fd = open("log.txt", O_WRONLY|O_CREAT|O_TRUNC, 0644); dup2(fd, 1);
  3. fd = open("log.txt", O_WRONLY|O_CREAT|O_APPEND, 0644); dup2(1, fd);
  4. fd = open("log.txt", O_WRONLY|O_CREAT|O_APPEND, 0644); dup2(fd, 1);

>> appends, so O_APPEND, not O_TRUNC. dup2(old, new) makes new a copy of old, and we want fd 1 to become the file. Option 3 has the arguments backwards.

C · Index structures

10 · LBN

Blocks are 4096 bytes. Which logical block number holds byte offset 100,000?

100,000 / 4096 = 24.4, so 24. Lesson 3

11 · Extents

A file's extents, as (starting PBN, length): (500, 4) (120, 3) (900, 6). Which physical block holds LBN 8?

8 − 4 = 4, past the first extent. 4 − 3 = 1, past the second. 1 into the third: 900 + 1 = 901.

12 · First indirect offset

1024-byte blocks, 4-byte addresses, 12 direct pointers, then single, double and triple indirect. What is the smallest byte offset that needs the single indirect block?

12 × 1024 = 12,288. The address size doesn't matter here.

13 · First double offset

Same inode. What is the smallest byte offset that needs the double indirect block?

p = 1024 / 4 = 256. Direct and single cover 12 + 256 = 268 blocks. 268 × 1024 = 274,432.

14 · Max file size

2048-byte blocks, 8-byte addresses. The inode has 10 direct pointers, 1 single and 1 double indirect, and no triple. Largest file, in bytes?

p = 2048 / 8 = 256. Blocks = 10 + 256 + 256² = 65,802. × 2048 = 134,762,496. Watch the 8-byte addresses: with 4 you'd get p = 512.

15 · Reads

Same inode as Q12, already in memory, nothing else cached. How many disk reads to read the byte at offset 300,000?

LBN 292 is past 268, so it's under the double indirect: read the double block, then a single block, then the data block. 3.

16 · Block size

File system B has larger blocks than A. Which are true? Pick all that apply.

  1. B needs fewer disk accesses for the same big file
  2. B reads one individual block faster
  3. B wastes less space on tiny files
  4. B usually has higher throughput

Bigger blocks: fewer blocks per file, so fewer seeks, and higher throughput. But each block takes longer to transfer, and a 100-byte file still fills a whole (bigger) block, so more internal fragmentation.

D · Paths and links

17 · Path reads

Read the first byte of /usr/lib/x/a.txt. Nothing is in memory; each inode is in its own block; each directory fits in one block. Fewest disk reads?

Four names after the root, so k = 4. Directories /, usr, lib, x cost 2 reads each (8), then the file's inode and first data block (2). 2 × (4 + 1) = 10. Lesson 4 §2

18 · Path reads, variant

Same path, but the root inode is already in memory, and you only open() the file without reading any data. Disk reads?

Start from 10. The cached root inode saves 1. Not reading a byte drops the file's data block, which saves 1 more. 8. You still read the file's inode, since open checks permissions.

19 · Link count

touch a; ln a b; ln -s a c. What is the link count of a's inode?

The hard link b adds a second directory entry for the same inode: 2. The symlink c is a separate file holding the text "a", so it doesn't change a's count. 2.

20 · Dangling

Then rm a. Which still works?

  1. cat c only
  2. cat b only
  3. Both cat b and cat c
  4. Neither of them

b is the same inode, now with link count 1, so the data survives. c holds the path "a", which no longer exists, so it dangles.

21 · Which ln fails

Which command fails?

  1. ln -s /mnt/usb/notes mynotes
  2. ln report.txt copy.txt
  3. ln /mnt/usb/notes mynotes
  4. ln -s .. up

Assuming /mnt/usb is a different file system, a hard link can't cross it, because inode numbers only mean something on one disk. Symlinks can cross file systems and point at directories.

22 · Vocabulary

Which structure holds a file's LBN → PBN map?

  1. Its directory entry
  2. The open-file table
  3. The parent directory
  4. The file's inode

The inode holds metadata plus the block map, but no name. A directory entry is just name → inode number.

E · Coherence (MSI and MESI)

23 · MESI read miss

MESI. Core 1 read-misses on a line no other cache holds. Core 1's new state?

  1. M
  2. S
  3. E
  4. I

Nobody else has it, so Exclusive. In MSI the same read gives S. That's one of the two places the protocols differ.

24 · Course MSI

Course MSI diagram. Core 1 holds a line in M, and Core 2 reads it. Core 1's new state?

  1. I, after a write-back
  2. S, after a write-back
  3. M, with no change
  4. S, with no write-back

On the course MSI diagram a remote read or write takes M to I. MESI would give S. That's the other difference.

25 · Legal pairs

Two MESI caches hold the same memory line. Which pair can occur?

  1. E and S
  2. S and S
  3. M and S
  4. E and E

M and E mean "only I have it", so they pair only with I. The legal pairs are I with anything, and S with S.
