Bytes, Stages & New Instructions

Turn any y86 line into bytes and back. Then write what each of the six SEQ stages does for any instruction, including one you've never seen, or say exactly why the hardware can't run it.

Your win for today: these are the first six Quiz 2 learning goals. They draw on the y86 Reference and the SEQ implementation diagram, both of which you get during the quiz, so keep them open while you work. About 30 minutes: Part A is encoding (10 min), Part B is the stage notation (10 min), and Part C is new instructions (10 min).

Warm-up: interleaved recall

With forwarding, how many bubbles does a load/use hazard (mrmovq followed immediately by a use of its destination) cost?

  1. 0
  2. 3
  3. 1
  4. 2

One stall. valM exists only at the end of Memory, so the consumer waits one cycle in Decode and then takes m_valM (Lesson 1). Keep that “when is the value first known?” question in mind. Part B answers it for every instruction.

Without prediction, ret costs 3 bubbles. Which SEQ stage produces the return address?

  1. Memory (valM = M8[valA])
  2. Execute (valE)
  3. Fetch (valC)
  4. Decode (valA)

The return address is read from the stack in Memory, and the next PC is valM. Fetch can't continue until ret has reached Memory, which is why it costs 3 bubbles. Part B shows this in the stage table.

Part A · Assembly ⇄ bytes

Every instruction is built from at most four fields, always in the same order y86 Reference, “Instructions Encoding”:

Byte(s)FieldPresent when
0icode:ifun, one hex digit eachalways
1rA:rB, one hex digit each (F = no register)the instruction names a register
next 8V, D or Dest: 8 bytes, little-endianthe instruction has a constant

That gives four sizes, and you should know them by heart. They are exactly the valP = PC + n values in Part B.

BytesInstructionsWhy
1halt 00 · nop 10 · ret 90no registers, no constant
2rrmovq/cmovXX 2fn · OPq 6fn · pushq A0 · popq B0registers, no constant
9jXX 7fn · call 80constant but no register byte
10irmovq 30 · rmmovq 40 · mrmovq 50registers and a constant

Worked example: rmmovq %rcx, 16(%rsp)

  1. rmmovq is icode 4, ifun 0, so byte 0 is 40.
  2. The register byte is rA:rB. rA is the source, %rcx = 1. rB is the base, %rsp = 4. So byte 1 is 14.
  3. D = 16 = 0x10. As 8 bytes, least-significant first: 10 00 00 00 00 00 00 00.

Result: 40 14 10 00 00 00 00 00 00 00.

The five traps that cost marks
  1. mrmovq D(rB), rA lists the destination last, but it still goes in the rA slot. So mrmovq 8(%rbx), %rax encodes as 50 03 … (rA = %rax = 0, rB = %rbx = 3). For both memory moves, the register inside the parentheses is always rB.
  2. Unused register slots are F. irmovq is 3 0 F rB, and pushq/popq are A/B 0 rA F. For example, pushq %rsi encodes as a0 6f.
  3. Little-endian applies to the 8-byte constant only. 0x1234 becomes 34 12 00 00 00 00 00 00. Never reverse the icode:ifun or rA:rB bytes.
  4. Negative constants are two's complement across all 8 bytes. −8 becomes f8 ff ff ff ff ff ff ff, and −1 is all ff.
  5. OPq rA, rB computes rB OP rA. So subq %rax, %rbx (encoded 61 03) sets %rbx ← %rbx − %rax.

Two lookups from the reference sheet you'll use constantly: the ifun row is add sub and xor mul div mod = 0–6 for OPq, and (always) le l e ne ge g = 0–6 for jXX/cmovXX. Register numbers follow %rax %rcx %rdx %rbx %rsp %rbp %rsi %rdi = 0–7, then %r8–%r14 = 8–E.

Encode mrmovq -8(%rbp), %rdi.

  1. 50 57 f8 ff ff ff ff ff ff ff
  2. 50 75 f8 ff ff ff ff ff ff ff
  3. 50 75 08 00 00 00 00 00 00 00
  4. 50 75 ff ff ff ff ff ff ff f8

The destination %rdi = 7 goes in rA, and the base %rbp = 5 goes in rB, so byte 1 is 75 (trap 1). −8 is …fff8, written least-significant byte first, so it starts with f8 (traps 3 and 4).

Which instruction is 63 21?

  1. xorq %rcx, %rdx
  2. andq %rdx, %rcx
  3. subq %rdx, %rcx
  4. xorq %rdx, %rcx

Byte 0 is 6 3, which is OPq with ifun 3 = xor. Byte 1 is 2 1, so rA = %rdx and rB = %rcx. The assembly lists rA first: xorq %rdx, %rcx.

How many bytes long is call 0x40?

9 bytes: 1 for 80 plus an 8-byte Dest. There's no register byte, so the destination starts at PC+1. That's why Part B has valC = M8[PC+1] for call and jXX, but M8[PC+2] for irmovq, rmmovq and mrmovq.

This code starts at 0x200: a0 3f 50 13 10 00 00 00 00 00 00 00 60 10 b0 3f 90. At what address is the ret, and what is the second instruction?

  1. 0x20f, mrmovq 16(%rcx), %rbx
  2. 0x210, rmmovq %rcx, 16(%rbx)
  3. 0x210, mrmovq 16(%rbx), %rcx
  4. 0x216, mrmovq 16(%rbx), %rcx

pushq %rbx (2), mrmovq 16(%rbx), %rcx (10; 50 is mrmovq, rA = 1 = %rcx is the destination, rB = 3 = %rbx is the base), addq %rcx, %rax (2), popq %rbx (2). That's 16 bytes in hex, 0x200 + 0x10 = 0x210, and 90 is ret.

Now drill until both directions feel automatic. The instructions are random, so aim for 8 correct in a row. In the bytes → assembly drill, any spelling that produces the same bytes counts, so $16 and $0x10 are both fine.

Part B · The six SEQ stages, in course notation

SEQ runs every instruction through the same six phases, in this order, within one clock cycle slides 1.5 “rrmovq three ways”; CS:APP §4.3.1. Here's what each phase does in plain English. The goals ask you to explain this, so practise saying it in your own words.

PhaseWhat it doesSignals it may use (slide 27)
FetchReads the instruction bytes at PC and splits them into icode, ifun, rA, rB and valC. Computes valP, the address of the next instruction in order.icode, ifun, rA, rB, valC, valP, PC, instruction memory
DecodeReads up to two registers from the register file into valA and valB.rA, rB (or %rsp), valA, valB
ExecuteRuns the ALU once to compute valE. OPq sets the condition codes here, and jXX/cmovXX compute Cnd here.valA, valB, valC, valE, 0, ±8, CC, Cnd, cond, setCC, ifun
MemoryMakes at most one data-memory access: reads into valM or writes a value.valA, valE, valM, valP, memory
WritebackWrites up to two registers: port E gets valE and port M gets valM.Cnd, rA, rB (or %rsp), valE, valM
PC updateSets PC to the next instruction's address.PC, Cnd, valC, valM, valP

Don't memorise the table. Rebuild it from five rules.
  1. Need a constant? Fetch reads valC. It's at PC+2 if there's a register byte, otherwise PC+1. valP is PC plus the instruction length from Part A.
  2. Need a register's value? Decode reads it. The register used as a value or data goes in valA. The register used as a base, second operand or the stack pointer goes in valB.
  3. Need arithmetic or an address? Execute computes one valE. The stack instructions always produce the new %rsp here: −8 for push/call, +8 for pop/ret.
  4. Touch data memory? Memory does it. A write stores valA (or valP for call, which is the return address). A read produces valM.
  5. Change a register? Writeback: valE goes to a register through port E, and valM through port M. Then PC update chooses among valP, valC and valM.
Two details students miss

pop and ret read memory at valA, the old %rsp, not at valE. The value on top of the stack is at the current %rsp, and valE = %rsp + 8 is only the new stack pointer. That's why Decode reads %rsp twice. In contrast, push and call write at valE = %rsp − 8.

jXX reads no registers. It only uses the condition codes, which a previous OPq set. cmovXX computes Cnd but does not set CC. Only OPq sets CC.

Which instructions leave the Memory stage empty? Select all that apply.

  1. OPq
  2. call
  3. irmovq
  4. popq
  5. jXX

Only instructions that move data to or from memory use the Memory stage: rmmovq, mrmovq, push, pop, call and ret. call writes the return address (M8[valE] = valP), and pop reads valM.

For popq %rax with %rsp = 0x100, which pair is right?

  1. Reads M8[0x108]; %rsp becomes 0x108
  2. Reads M8[0xf8]; %rsp becomes 0xf8
  3. Reads M8[0x108]; %rsp becomes 0x100
  4. Reads M8[0x100]; %rsp becomes 0x108

valA = valB = 0x100. valE = valB + 8 = 0x108, which becomes the new %rsp. valM = M8[valA] = M8[0x100], which is written to %rax.

Which instruction is the only one in the standard ISA that writes two registers in Writeback?

  1. call
  2. popq
  3. mrmovq
  4. ret

popq writes %rsp through port E and rA through port M. Two write ports means at most two register writes per instruction, which matters in Part C.

Now sort them. Each drill shuffles one instruction's operations and adds one or two distractors that belong in “not used”. Do all of them. The last two are new instructions, as a preview of Part C.

Part C · A new instruction: can SEQ run it?

The quiz goal says: “Given a, possibly new, instruction, list the operations at each phase, or explain why the instruction cannot be executed.” To answer, check the instruction against what the SEQ hardware actually has slides 1.6, “Why can't we have addm?”, and slide 27 of 1.5:

The hardware budget: one of each
  • Fetch: one constant valC, at most.
  • Decode: two register reads, valA and valB.
  • Execute: one ALU operation. The ALU's A input can be valA, valC or ±8. Its B input can be valB or 0. So you can compute valB+valC, valA+0 or valB−8, but not valA+valC (both on the A side) and not anything involving valM.
  • Memory: one access. The address is valE or valA. The data written is valA or valP.
  • Writeback: two register writes. Port E takes valE and port M takes valM.
  • PC update: one of valP, valC or valM, optionally chosen by Cnd.

If an instruction fits this budget, write its table. If it needs a second ALU operation, a second memory access, a third register write, or a value on a wire that doesn't exist, it can't be executed. Name the specific resource that's missing.

Worked example 1: iaddq V, rB (R[rB] ← R[rB] + V). It fits.

The encoding is like irmovq with a new icode, say C 0 F rB V, so it's 10 bytes. It needs a constant (valC), one register read (valB = R[rB]), one add (valB + valC), and one register write.

Fetchicode:ifun = M1[PC] · rA:rB = M1[PC+1] · valC = M8[PC+2] · valP = PC+10
DecodevalB = R[rB]
ExecutevalE = valB + valC · set CC
Memory
WritebackR[rB] = valE
PC updatePC = valP

Setting CC is a design choice. It's an arithmetic operation like addq, so setting CC is the natural answer, but state your choice.

Worked example 2: addm D(rB), rA (R[rA] ← M[D + R[rB]] + R[rA]). It can't run.

This one comes from slides 1.6. The address D + R[rB] needs the ALU in Execute. The sum valM + valA would need the ALU a second time, after Memory. SEQ has one ALU and one valE, and no wire from valM back to the ALU. Adding a second ALU after Memory would also lengthen the critical path, so the clock cycle would get longer.

How to write a “can't” answer Name the conflict in one sentence: “addm needs two ALU operations (address = valB + valC, then valM + valA), but SEQ has a single ALU used once in Execute, and valM isn't available until after Execute.” Answers like “it's too complicated” earn nothing.

Your turn. Decide each one before opening the explanation.

jmpr rA: PC ← R[rA] (a jump through a register). Can SEQ run it as is?

  1. Yes: valA = R[rA]; PC = valA
  2. No. PC update can only choose valP, valC or valM, and no wire carries valA or valE to Next PC.
  3. No, because it would need two register reads
  4. Yes: valE = valA + 0; PC = valE

Check the diagram: Next PC's inputs are valP, valC, valM, icode and Cnd. The register value can reach valA and then valE, but neither one is connected to Next PC. It would need a new wire. (You could “cheat” by bouncing the value through memory, but that's a different instruction.)

incq rB: R[rB] ← R[rB] + 1, encoded in 2 bytes (D0 Fr). Can SEQ run it?

  1. Yes: valE = valB + 1
  2. Yes: valE = valB + 8, then divide by 8
  3. No. The ALU's constant inputs are only 0 and ±8, and a 2-byte encoding has no valC to supply the 1.
  4. No, because it writes a register in Writeback

The only constants wired into the ALU are 0 and ±8. Making it a 10-byte instruction with V = 1 gives you iaddq $1, rB, which does fit. That's the fix you'd suggest.

swapq rA, rB: exchange two registers. Can SEQ run it?

  1. No. Two register writes need valE and valM, but valM only comes from a memory read, and the ALU can pass through only one of the two values.
  2. Yes: R[rA] = valB; R[rB] = valA
  3. No, because Decode can only read one register
  4. Yes: valE = valA + 0; valM = valB; then write both

Writeback writes only valE (port E) and valM (port M), and nothing connects valA or valB directly to the register file's write ports. The ALU can carry one of the values through valE, but the other would have to arrive as valM, and valM is only produced by reading memory. So the answer is no.

mmmovq (rA), (rB): M[R[rB]] ← M[R[rA]], a memory-to-memory copy. Can SEQ run it?

  1. Yes: valM = M8[valA]; M8[valB] = valM
  2. Yes, since both addresses come from registers
  3. No, because it needs a constant
  4. No. It needs two data-memory accesses, a read and then a write, and the Memory stage does exactly one.

The budget is one memory access per instruction. Even ignoring that, the data written must be valA or valP, not valM.

ldinc (rB), rA: R[rA] ← M[R[rB]], then R[rB] ← R[rB] + 8 (a load that advances a pointer). Can SEQ run it?

  1. No, because it writes two registers
  2. Yes. It has the same shape as popq, with rB in place of %rsp.
  3. No, because it needs two ALU operations
  4. Yes, but only if it's 10 bytes

Decode: valA = R[rB], valB = R[rB]. Execute: valE = valB + 8. Memory: valM = M8[valA]. Writeback: R[rB] = valE, R[rA] = valM. PC: valP (2 bytes). Two writes are fine because there are two ports. It's the last instruction in the sorter drill above.

Harder: pushi V, which pushes an immediate (M8[R[%rsp]−8] ← V; %rsp −= 8). Can SEQ run it?

  1. Yes: like call, with valC as the data
  2. Yes: valE = valC + (−8)
  3. No, not as wired. Memory may only write valA or valP, and valC isn't routed to the memory's data input. It needs a new wire, valC → Data.
  4. No, because it needs three register reads

The address part is fine: valB = R[%rsp], valE = valB + (−8). The data part fails. Slide 27 lists only valA, valE, valM and valP for Memory, and the diagram's Data block takes only valA and valP. call gets away with it because what it pushes is valP. Watch for this kind of trap: the arithmetic fits, but a wire is missing.

Pipelines use the same notation The goal “given a pipeline description, describe each stage in y86 notation” asks for the same skill on a made-up pipeline, for example a 3-stage machine that does R[rB] = R[rA] * R[rB]; PC = PC + 2. Use the same symbols, and state what each stage reads and writes. If you meet one on a practice quiz, paste it to me and we'll do it together.
