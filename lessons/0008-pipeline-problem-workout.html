Pipeline Problem Workout

How to count stalls, squashes and CPI for a whole program with loops, using one procedure that works every time.

Your win for today: given a 10–20 line loop program and a pipeline (stalling or forwarding, plus a predictor), produce the data stalls, squashed instructions, control stalls and CPI, and get them right. That's I11.1, I11.2, I11.4 and the questions your classmates will answer about your P10.2 program. The last section fixes the R2.4 slip ("which register holds what") in five minutes. About 45 minutes. Work with paper beside you.

Warm-up: interleaved recall

From Lesson 7: which instruction writes two registers in Write-back?

  1. pushq
  2. mrmovq
  3. popq
  4. call

popq rA: R[%rsp] = valE and R[rA] = valM. That's why a popq can cause a hazard on %rsp as well as on rA. Both I11.2 and R2.9 rely on it.

Which register does andq %rsi, %rsi write?

  1. None, it only sets the condition codes
  2. %rsi
  3. %rax

Every OPq writes R[rB] = valE, even when it's used purely as a test. This matters in your own P10.2 program (section 5).

1 · The whole rulebook on one card

Everything below is from slides 2.3–2.5 and the I11 answer keys. These rules reproduce those keys exactly.

Data hazards: count the slots, not the lines

Distance = how many pipeline slots the reader is behind the writer. Every instruction in between counts, and so does every bubble: earlier stalls and squashed wrong-path instructions included.

  • No forwarding (stalling): distance 1 → 3 stalls, 2 → 2, 3 → 1, 4+ → 0.
  • Forwarding: only load → use at distance 1 costs anything: 1 stall. A load is mrmovq, or popq for its rA. Everything else is free.
  • If several registers are late, the instruction stalls for the worst one only. Stalls don't add.

Who writes what: OPq, rrmovq, irmovq and cmovXX write rB. mrmovq writes rA. popq writes rA and %rsp. pushq, call and ret write %rsp. rmmovq and jumps write nothing. Only read-after-write is a hazard: two writes to the same register, or a write after a read, cost nothing. Condition codes never stall.

Control hazards
  • Conditional jump, no prediction: 2 stall cycles every time, taken or not. These are control stalls.
  • Conditional jump with a predictor: 0 if the guess was right, otherwise 2 squashed instructions. Squashes are not stalls, so the quiz asks for them separately.
  • jmp and call: 0 always. The target is valC, known in Fetch. A jmp is never "mispredicted".
  • ret: 3 control stalls.
CPI for a whole program (slides 2.5)

cycles = instructions + 4 + data stalls + control stalls + squashed, and CPI = cycles / instructions.

Instructions = instructions executed, counting the final halt and not counting squashed ones. The 4 fills the pipeline. The slides' own examples are 71/37 (no forwarding, no prediction) and 43/37 (forwarding, never taken: 37 + 4 + 2).

The exception: an instruction-mix question like I11.3 ("8% are branches…") says “ignore startup”. There it's CPI = 1 + Σ fraction × penalty, with no +4.

2 · The procedure (the course's “tips for peer problems”, made concrete)

  1. Trace the values. Don't skip this. Write the loop registers in a small table, one row per iteration, until the exit jump is taken. The result is two numbers: how many iterations, and which jumps are taken in which iteration. Most wrong answers start here.
  2. Cut the code into basic blocks: straight-line runs that execute the same number of times. Typically: setup (×1), loop body (×N), any skip-able piece (×k), tail (×1).
  3. Data stalls, per block, in two passes. For the first iteration the writers are the setup instructions. For later iterations the writers are from the previous iteration, reached around the back edge. Count the jump, the jmp, and any squashed or stalled slots in the distance. First and later iterations often differ, which is why answer keys say “1 stall … / 2 stalls … (8 times)”.
  4. Control. For each conditional jump, compare the outcome in each iteration with the predictor's guess. Unconditional jmps cost nothing.
  5. Add up and count instructions. Instructions = setup + Σ (block size × times run) + tail + halt.

Step 3, data stalls.

  • Line 7, iteration 1: %rax comes from line 2, which is 3 slots back (lines 2, 3, 4, then 7). That's 1 stall.
  • Line 8, iteration 1: %rcx comes from line 4. Line 7 plus its 1 bubble put it at distance 3: 1 stall. Notice how the earlier stall shrank this one.
  • Line 10, every iteration: %rbp comes from the line right above it, distance 1: 3 stalls × 7 = 21. (%rdi is also late, but it's less late, so the stalls don't add.)
  • Line 7, iterations 2–7: %rax comes from line 8 of the previous iteration. Lines 9, 10 (+3 bubbles), 11 and 12 are in between, which is far enough: 0.
  • Line 17: popq reads %rsp, which line 15's popq wrote 2 slots earlier: 2 stalls. The repeated %r10 is write-after-write, so it's not a hazard.

Total 1 + 1 + 21 + 2 = 25.

Step 4, control. “Never taken” is right 6 times and wrong once (iteration 7): 2 squashed. jmp costs 0.

Where a 26 usually comes from You probably added one stall too many in one of these places: (a) line 8 counted as 2 because you forgot that line 7's bubble also delays line 8; (b) line 17 counted as 3 by treating it as adjacent to line 15, when line 16 sits between them; (c) a stall on line 7 in a later iteration. Check which one you did. It tells you which rule to drill.

For completeness: instructions = 3 + 7×5 + 6 jmps + 4 tail + halt = 49, so CPI = (49 + 4 + 25 + 2)/49 = 80/49 ≈ 1.63.

4 · Your turn: I11.4 (the peer problem)

    irmovq $5, %rbx          loop:  addq   %rax, %r8
    irmovq $-1, %rax                je     End
    irmovq list, %rdi               mrmovq 0(%rdi), %r9
    irmovq $8, %rsi                 rrmovq %r11, %r10
    irmovq $100000, %r11            subq   %r9, %r10
    rrmovq %rbx, %r8                cmovg  %r9, %r11
                                    addq   %rsi, %rdi
    list: 5, 10, 13, 2, 5           jmp    loop
                             End:   rrmovq %r11, %rax
                                    halt

Stalling (no forwarding) and predict always taken. Do steps 1–5 on paper before you check any answer.

Step 1: how many times does the loop body (mrmovq … jmp) run?

%r8 starts at 5, and each pass adds −1: 4, 3, 2, 1, 0. je End is taken on the 5th test, so the body runs 4 times and only touches list[0..3]. What the program computes (the min, 2) doesn't matter here.

How many instructions are squashed?

je is guessed taken every time, but it's actually not taken in 4 of its 5 executions, so 4 × 2 = 8. The jmp never squashes.

How many cycles does the processor stall due to data hazards?

15 = 3 + 4 × 3:

  • addq %rax, %r8 in the first pass: %r8 was written by the line directly above (rrmovq %rbx, %r8). That's 3. In later passes its writer is the previous addq, far away.
  • subq %r9, %r10: %r10 was written by the line directly above, 3 × 4. %r9 (distance 2, so 2 stalls) is hidden inside that wait.
  • cmovg reads %r9 after the wait, so it's free. Its condition codes are never a hazard.
  • mrmovq 0(%rdi) reads the %rdi from the previous pass: addq, jmp, addq, je, then 2 squashed slots. Far.

How many cycles does the processor stall due to control hazards?

0. With a predictor, jumps cost squashes, not stalls, and there's no ret.

CPI (2 significant figures)?

Instructions = 6 setup + 4 × 8 body + final addq, je + rrmovq, halt = 42. Cycles = 42 + 4 + 15 + 0 + 8 = 69. CPI = 69/42 ≈ 1.6.

loop_start:  andq   %rdx, %rdx        skip_add:  addq %r9, %rcx
             je     loop_end                     subq %r8, %rdx
             mrmovq 0(%rcx), %rsi                jmp  loop_start

             jle    skip_add
             addq   %rsi, %rax        array: 15, -5, 0, 7    (5 irmovq setup lines)

How many instructions will be squashed?

jle skip_add is taken for −5 and 0: 2 mispredictions. je loop_end is taken once, at the end: 1 misprediction. Total 3 × 2 = 6.

With forwarding, how many cycles does it stall due to data hazards?

With forwarding only load → use costs anything: mrmovq … %rsi followed immediately by andq %rsi, %rsi, 1 × 4 iterations = 4. (subq %r8, %rdx → jmp → andq %rdx, %rdx is forwarded for free.)

CPI (remember the halt)?

Instructions = 5 + (9 + 8 + 8 + 9) + final andq, je + halt = 42 (iterations with 15 and 7 run the addq, so they're 9 long). Cycles = 42 + 4 + 4 + 6 = 56. CPI = 56/42 ≈ 1.33.

Harder: the same program on the stalling-only pipeline (no forwarding). How many data-stall cycles?

24, from three sources:

  • andq %rsi, %rsi right after the load: 3 × 4 = 12.
  • addq %rsi, %rax: %rsi was last written by andq %rsi, %rsi (OPq writes rB!), 2 slots back (with jle in between): 2 × 2 runs = 4.
  • andq %rdx, %rdx after subq %r8, %rdx; jmp: distance 2, so 2 × 4 = 8. The first andq is far from the setup.

This is the trap a classmate would hit. The jmp counts as a slot, and the test andq is a writer.

7 · Who holds what: R2.4, R2.5, R2.9, R2.10

Three facts answer all of these
  1. Staircase: with no stalls, if instruction i is in stage S, then i+1 is one stage behind and i−1 one stage ahead.
  2. Naming: E_dstM (capital) is the pipeline register at the start of Execute, holding the instruction now in Execute. d_dstM (lowercase) is the signal computed in Decode by the instruction now in Decode. Either way, the name points at the instruction in that stage.
  3. If that instruction isn't in the question, the answer is NONE.

Your R2.4 miss, explained. First instruction in Memory → second in Execute → third in Decode. The question shows only two instructions, so d_dstM belongs to an unknown instruction: NONE. You answered %r10, the second instruction's dstM, which actually sits in E_dstM at that moment. Your variant-2 answer (E_dstM = %r8) shows you have the staircase right. The error was naming the wrong stage.

mrmovq 8(%rbx), %rdi then addq %rdi, %rsi. When the mrmovq is in Write-back, what is in M_dstE?

  1. %rdi
  2. %rsi
  3. %rbx
  4. NONE

addq uses the loaded %rdi immediately, so even with forwarding it's held in Decode for 1 cycle while a bubble goes into Execute. When mrmovq reaches W, the stage just behind it (M) holds that bubble, and a bubble's dstE is NONE. Without forwarding there are 3 bubbles, and the answer is still NONE. The trap is skipping the stall check and answering %rsi. Ask “is there a stall?” before you walk the staircase.

R2.9 shape: popq %r12; nop; xorq %r12, %rax. With forwarding, where does the xorq get %r12, with no stall?

  1. W_valM
  2. M_valE
  3. m_valM
  4. It must stall

When xorq is in Decode, popq is 2 ahead, in Memory, reading the value right now, so m_valM. (%r12 is the popped value, so it travels via valM. valE is the new %rsp.) Distance 1 would be impossible (stall). Distance 3 would be W_valM. Distance 4+ comes from the register file.

R2.10 shape, PIPE- (no hazard handling): rrmovq %rbx, %rax; addq %r11, %rsi; mrmovq 0x5269(%rax), %r11. How many nops before line 3?

nops = 3 − (instructions already between). One instruction is between, so 2. It's the same table as stalling, just paid in nops.

8 · Instruction-mix CPI (I11.3)

You had 2/4 here. The key's formula, with its three penalties: CPI = 1 + (load/use fraction × 1) + (conditional-branch fraction × 2 × miss rate) + (ret fraction × 3). With no predictor the miss rate is 1, since every conditional branch pays. Watch the nested percentage: “8% are branches, 65% of those are conditional” means 0.08 × 0.65. With forwarding, only the “hazard that can't be avoided by forwarding” fraction pays the 1.
