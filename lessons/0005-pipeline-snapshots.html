Pipeline Snapshots

Freeze the pipeline at one clock cycle and read off what is in every stage and every pipeline register.

Your win for today: answer the four practice-quiz question types that the forwarding drills don't cover. Those are “what stage is X in?” (R2.3), “what's in E_dstM?” (R2.4), “what is d_valA?” (R2.5) and “how many nops?” (R2.10). All four use one picture: a staircase. About 15 minutes.

1 · The staircase

With no stalls, each instruction enters Fetch one cycle after the one before it. Freeze any cycle and the program sits diagonally across the stages. An instruction k lines earlier is k stages further along CS:APP 3e §4.4, Fig. 4.33.

Look at cycle 5: irmovq is in W, rrmovq in M, addq in E, subq in D, halt in F.

Most snapshot questions are this staircase plus one fact. Decode is where an instruction reads registers. Write-back is where it writes them.

PIPE- (no hazard handling). When subq reads %rcx, what stage is the rrmovq in?

Ln_1:    rrmovq   %rdi, %rcx
Ln_2:    irmovq   $0xcf8a, %rdx
Ln_3:    irmovq   $0xd7e, %r10
Ln_4:    subq     %rcx, %rbx
  1. Fetch
  2. Decode
  3. Execute
  4. Memory
  5. Write-back

subq reads in Decode. rrmovq is 3 lines earlier, so it is 3 stages ahead of D: D → E → M → W. It is writing %rcx in that very cycle, and the register file only shows the new value next cycle. So subq reads the stale value. That's why distance 3 is still a hazard in PIPE-.

2 · Pipeline registers belong to the instruction in that stage

Each stage begins with a pipeline register named after it (F, D, E, M, W). An UPPERCASE prefix names a field stored in one: E_dstM is the dstM field of the instruction currently in Execute CS:APP §4.5.2–4.5.3, Fig. 4.41. So find which instruction is in E, then ask what its dstM is.

RegisterFields it holds (PIPE)
FpredPC
Dicode, ifun, rA, rB, valC, valP
Eicode, ifun, valC, valA, valB, dstE, dstM, srcA, srcB
Micode, Cnd, valE, valA, dstE, dstM
Wicode, valE, valM, dstE, dstM

(Also a stat field in D–W; not on this quiz.) Decode works out dstE/dstM from rA/rB, which is why they first appear in E.

Stalling processor. %r14 = 0x5000, %rax = 0x1000. When the first instruction is in Memory, what does E_dstM hold?

mrmovq 0xe00(%r14), %rbx
mrmovq 0x400(%rax), %r8
  1. %rbx
  2. %rax
  3. %r8
  4. NONE

First is in M, so the second (one line later) is one stage behind, in E. It's a load into %r8, so its dstM = %r8. No stall happens (the second reads %rax, which the first doesn't write). The register values are a distraction. %rbx is in M_dstM, not E_dstM.

3 · What Decode reads, what Write-back writes

This one table answers every “what is d_valA / E_dstE / …” question. It comes straight from the SEQ stage tables, CS:APP Figs. 4.18–4.21 CS:APP §4.3.1.

mrmovq D(rB), rA—rB—rA

Why does ret / popq read %rsp twice? valA = old %rsp is the address to read (valM ← M8[valA]). valB = old %rsp goes through the ALU to make the new stack pointer (valE ← valB + 8). Two jobs need two copies. pushq/call instead write to M8[valE], the already-decremented address.

PIPE trap: for call and jXX, there's no srcA, but d_valA isn't empty. The “Sel+Fwd A” block puts valP in it. That way call can push the return address, and a mispredicted jXX can recover the fall-through address (CS:APP §4.5.7).

A ret is in Decode. Which best identifies the value assigned to d_valA?

  1. R[%rbx]
  2. valP
  3. M8[%rsp]
  4. R[%rsp]

ret: srcA = %rsp, so d_valA = R[%rsp], the address of the return address. (With forwarding it may come from a later stage, but it's still %rsp's value.) M8[%rsp] is what Memory reads using valA. That becomes valM.

4 · PIPE-: counting nops by hand

No stalling and no forwarding means the programmer must space instructions out. A value written in W can be read in Decode the next cycle slides 2.3, “Recall stalling”. So the consumer must be at least 4 lines after the producer:

The rule nops needed = 4 − distance (zero if distance ≥ 4). valE or valM makes no difference here, since everything waits for W. Nops you've already inserted count toward later distances.

Worked through R2.10:

Ln_0:  mrmovq 0x43ad(%rsi), %rax
Ln_1:  mrmovq 0xe2b5(%r8),  %rdi
Ln_2:  rrmovq %rax, %rbp            # reads %rax from Ln_0: distance 2 → 2 nops
Ln_3:  mrmovq 0x3c6b(%rdi), %rcx    # reads %rdi from Ln_1: distance 2 + 2 nops = 4 → 0
Ln_4:  rrmovq %r13, %r10
Ln_5:  mrmovq 0x4831(%rbx), %rdx
Ln_6:  rmmovq %r10, 0x439(%r10)     # reads %r10 from Ln_4: distance 2 → 2 nops

Ln_0–Ln_2 with 2 nops on PIPE- (no forwarding): rrmovq reads %rax the cycle after mrmovq's W. No stall needed.

PIPE-. How many nops before xorq?

mulq   %rsi, %rax
nop
xorq   %rax, %r11
  1. 1 nop
  2. 2 nops
  3. 3 nops
  4. 4 nops

The existing nop already makes the distance 2. 4 − 2 = 2 more. (On the forwarding pipeline it would need 0: M_valE.)

4½ · When two stages hold the same register

Freeze the pipeline and several later stages may all be about to write the same register. Decode must take the newest value. That's the one from the instruction closest to Decode, since it came latest in program order. So the forwarding logic checks the stages nearest-first CS:APP §4.5.7, d_valA HCL:

  1. d_srcA == e_dstE → e_valE
  2. d_srcA == M_dstM → m_valM
  3. d_srcA == M_dstE → M_valE
  4. d_srcA == W_dstM → W_valM
  5. d_srcA == W_dstE → W_valE
  6. otherwise → the value from the register file (selectA's output)

Inside one stage, valM is checked before valE. The only instruction with both a dstE and a dstM is popq. For popq %rsp both are %rsp, and the popped value must win. This order is also the spec for Lab 4's forwardA(): a chain of ifs in exactly this order. Before you write it, ask yourself: what should happen when d_srcA is R_NONE, and some stage's dst is also R_NONE?

Forwarding processor, no stalls. Where does the last instruction's valA come from?

irmovq $0x7, %rdx
mrmovq 0(%rsp), %rdx
irmovq $0x1, %rcx
rrmovq %rdx, %rsi
  1. W_valE
  2. m_valM
  3. M_valE
  4. W_valM

Both earlier writers of %rdx are still in flight: irmovq is in W (W_valE) and mrmovq is in M. The mrmovq is newer and is checked first, so m_valM wins. Taking W_valE would read the stale 0x7.
