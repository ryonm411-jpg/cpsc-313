Part A · Calling conventions (recall these cold)

Straight from the y86 Calling Conventions sheet. You get this sheet in the quiz, but knowing it from memory saves minutes.

RoleRegister(s)
Return value%rax
Arguments 1–6 (in order)%rdi, %rsi, %rdx, %rcx, %r8, %r9
Arguments 7+pushed on the stack, in reverse order
Too-big arg (e.g. a struct)passed on the stack (don't skip the next register for later args)
Stack pointer%rsp
Frame (base) pointer%rbp
Caller-saved (scratch; callee may clobber)%rax, %rdi, %rsi, %rdx, %rcx, %r8, %r9, %r10, %r11
Callee-saved (must be restored before return)%rbx, %rbp, %r12, %r13, %r14
What "calling convention" means (define it) A calling convention is the agreed set of rules callers and callees follow so they can cooperate without seeing each other's code: where arguments go, where the return value goes, and who is responsible for preserving which registers across a call. It's a contract, not something the hardware enforces.
Compare & contrast (a favourite short-answer)
  • Registers vs. stack for arguments: registers are fast (no memory traffic) but few, so only the first 6 go in registers; the rest spill to the stack.
  • Caller-saved vs. callee-saved: caller-saved shifts the saving cost to the caller only when it actually has a live value to protect; callee-saved lets a caller assume those registers survive a call, at the cost of the callee saving them if it uses them. The split lets each side avoid needless saves.

A function calls another and needs the value in %rcx to survive the call. Whose job is it to save %rcx, and why?

  1. The callee — %rcx is callee-saved
  2. The caller — %rcx is caller-saved (scratch), so the callee may overwrite it; if the caller cares, the caller must save/restore it
  3. Neither — %rcx is always preserved
  4. The callee, because %rcx holds the 4th argument

%rcx is caller-saved (it's also the 4th argument register). The callee is free to clobber it, so a caller that needs it afterward must push it before the call and pop it after.

A function takes 8 long arguments. Where does the 8th argument go?

  1. In %r10
  2. In %rax
  3. On the stack (args 7 and 8 are pushed in reverse order, so arg 8 is pushed first)
  4. It's illegal to have more than 6 arguments

Args 1–6 use %rdi…%r9; args 7 and 8 go on the stack. They're pushed in reverse, so the 8th is pushed first and the 7th ends up at the lower address (nearer the top).

Part B · Assembler directives

Directives aren't instructions — they tell the assembler how to lay out the program in memory.

DirectivePurpose
.pos 0x100Place the following code/data starting at address 0x100.
.align 8Advance to the next multiple of 8 (so .quad data is aligned).
.quad 0x1FEmit one 8-byte value at the current position.
label:Name the current address so jmp/call/irmovq can refer to it.

Typical use: set up the stack and data before the code runs —

    .pos 0
    irmovq stack, %rsp      # initialise the stack pointer
    call main
    halt
    .pos 0x200
array:
    .quad 10
    .quad 20
    .quad 30
    .pos 0x300
stack:                       # %rsp starts here, grows downward

What does .pos 0x200 do?

  1. Tells the assembler the next item is placed at address 0x200
  2. Reserves 0x200 bytes of zeroed memory
  3. Jumps execution to 0x200 at runtime
  4. Sets %rsp to 0x200

.pos is an assemble-time layout directive: it sets where the following bytes land. It doesn't run, allocate, or move the stack pointer.

Part C · Shorthand notation

A learning goal is to turn an instruction + its English description into the compact register-transfer form like R[rB] = R[rA] * R[rB]. Use R[x] for a register's value and M[addr] for a memory word.

InstructionShorthand
mulq %rA, %rBR[rB] = R[rB] * R[rA]
irmovq $V, %rBR[rB] = V
mrmovq D(%rB), %rAR[rA] = M[R[rB] + D]
rmmovq %rA, D(%rB)M[R[rB] + D] = R[rA]
pushq %rAR[rsp] = R[rsp] − 8; M[R[rsp]] = R[rA]
popq %rAR[rA] = M[R[rsp]]; R[rsp] = R[rsp] + 8

Remember the OPq order: R[rB] = R[rB] OP R[rA] — the destination rB is also the left operand.

Write the shorthand for subq %rsi, %rdi.

  1. R[rsi] = R[rsi] − R[rdi]
  2. R[rdi] = R[rsi] − R[rdi]
  3. R[rsi] = R[rdi] − R[rsi]
  4. R[rdi] = R[rdi] − R[rsi]

OPq %rA, %rB → R[rB] = R[rB] OP R[rA]. Here rA = %rsi, rB = %rdi, so R[rdi] = R[rdi] − R[rsi].

Part D · Encoding & the SEQ phases (quick pass)

Two more Quiz 1 goals: byte encoding ⇄ assembly, and the instruction-processing phases. Here's the compressed version; if you want the full drill-heavy treatment, Lesson 7 (in the Quiz 2 folder, but the skill is identical) has random generators for both directions.

Encoding in one breath

  • Byte 0 is icode:ifun (one hex digit each). Byte 1, when present, is rA:rB (F = none). A constant, when present, is 8 bytes little-endian.
  • Sizes: 1 byte (halt/nop/ret), 2 (rrmovq/OPq/pushq/popq), 9 (jXX/call), 10 (irmovq/rmmovq/mrmovq).
  • Register numbers: %rax…%rdi = 0–7, %r8…%r14 = 8–E, none = F. ifun for OPq: add sub and xor mul div mod = 0–6.

The six SEQ phases, in order

Every instruction flows through these within one clock cycle:

Fetch → Decode → Execute → Memory → Writeback → PC update
PhaseIn one line
Fetchread the instruction bytes at PC; split into icode/ifun/rA/rB/valC; compute valP (next address).
Decoderead up to two registers into valA, valB.
Executeone ALU op → valE; OPq sets condition codes; jXX/cmov compute Cnd.
Memoryat most one data read (→ valM) or write.
Writebackwrite up to two registers: port E ← valE, port M ← valM.
PC updateset PC to valP, valC, or valM.

Example notation (the form the quiz asks for), for pushq %rA:

Decode:    valA = R[rA];  valB = R[%rsp]
Execute:   valE = valB + (-8)
Memory:    M8[valE] = valA
Writeback: R[%rsp] = valE
PC update: PC = valP

How many bytes is irmovq $1, %rax, and why?

  1. 2 — one for the opcode, one for the register
  2. 10 — 1 opcode byte + 1 register byte + 8 bytes for the constant
  3. 9 — opcode plus an 8-byte constant, no register byte
  4. 1 — it's a simple move

irmovq has a register byte (3 0 F rB) and an 8-byte immediate, so 1 + 1 + 8 = 10. The 9-byte instructions (jXX, call) have a constant but no register byte.
