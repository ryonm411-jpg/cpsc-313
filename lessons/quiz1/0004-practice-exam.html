Section 1 · ISA & notation

Q1. Which best defines an instruction set architecture?

  1. The physical transistor layout and clock speed of a particular CPU chip
  2. The abstract contract between software and hardware — the instructions, registers, and memory model a compiler can target, independent of how the chip is built
  3. The set of compiler optimisation flags available for a language
  4. The operating system's table of available system calls

An ISA is the interface: what instructions exist, what registers and memory the program sees, how instructions are encoded. The transistor layout is the microarchitecture — one ISA can have many implementations (SEQ and PIPE both implement Y86).

Q2. In plain English, what does mrmovq 16(%rbx), %rax do?

  1. Stores %rax into memory at address %rbx + 16
  2. Loads into %rax the 8-byte value at memory address %rbx + 16
  3. Sets %rax = %rbx + 16
  4. Loads %rbx from the address %rax + 16

mrmovq = memory→register (a load). The memory operand is on the left: R[rax] = M[R[rbx] + 16].

Q3. Give the shorthand (register-transfer) form of rmmovq %rdx, 8(%rcx).

  1. M[R[rcx] + 8] = R[rdx]
  2. R[rdx] = M[R[rcx] + 8]
  3. M[R[rdx] + 8] = R[rcx]
  4. R[rcx] = R[rdx] + 8

rmmovq rA, D(rB) is a store: M[R[rB] + D] = R[rA], with rA = %rdx, rB = %rcx, D = 8.

Section 2 · C ⇄ Y86 (your focus area)

Q4. Consider this Y86 (%rdi = n, result in %rax):

f:
    irmovq $0, %rax
    irmovq $1, %r8
loop:
    addq %rdi, %rax        # sum += n
    subq %r8, %rdi         # n--
    jne loop
    ret

What loop shape is this, and can the body be skipped?

  1. A while loop — the body can run 0 times
  2. A for loop with a guard at the top
  3. A do-while — there is no check before loop:, so the body always runs at least once
  4. An infinite loop

Execution falls straight into loop: with no guard; the only branch is jne loop at the bottom. That's a do-while. Note the latent bug: called with n = 0, it decrements to −1 and loops billions of times (jne only stops at exactly 0).

Q5. The C is x = a - b; with a in %rdi, b in %rsi, x returned in %rax. A classmate wrote:

    rrmovq %rsi, %rax      # rax = b
    subq %rdi, %rax        # rax = rax - rdi
    ret

Does this correctly implement a - b?

  1. Yes — it computes a − b
  2. No — it computes b − a (the operands are reversed); it should copy a then subtract b
  3. No — subq between two registers is illegal
  4. No — the result must be placed in %rdx, not %rax

It loads b into %rax then does rax = rax − rdi = b − a. The correct version: rrmovq %rdi, %rax; subq %rsi, %rax. This is exactly the "operand order got flipped" trap.

Q6. Translating b[1] = b[0]; (b is a long* in %rcx), which is correct and legal Y86?

  1. mrmovq (%rcx), 8(%rcx)
  2. mrmovq 8(%rcx), %rax ; rmmovq %rax, (%rcx)
  3. mrmovq (%rcx), %rax ; rmmovq %rax, 8(%rcx)
  4. irmovq (%rcx), %rax ; rmmovq %rax, 8(%rcx)

b[0] is at (%rcx), b[1] at 8(%rcx). Load b[0], then store it to b[1]. Option 1 is memory-to-memory (illegal). Option 2 copies the wrong way. Option 4 uses irmovq (immediate only).

Q7. (on paper) Write Y86 for this function. a is in %rdi, b in %rsi, return in %rax.

long max(long a, long b) {
    if (a >= b) return a;
    return b;
}
Reveal a correct solution 
max:
    rrmovq %rdi, %rax      # assume a is the answer
    rrmovq %rdi, %r8
    subq %rsi, %r8         # r8 = a - b   (flags describe a vs b; r8 is a scratch copy)
    jge done               # if a - b >= 0, i.e. a >= b, keep a
    rrmovq %rsi, %rax      # otherwise answer is b
done:
    ret

Key moves: copy a into a scratch register before subtracting so you don't destroy a (subq is destructive, and there's no cmpq). jge after subq %rsi,%r8 tests a ≥ b. Many equivalent answers exist; yours is right if it never clobbers a/b before they're used and picks the correct branch.

Section 3 · Calling conventions & stack frames

Q8. Which register holds the third integer argument to a function?

  1. %rsi
  2. %rdx
  3. %rcx
  4. %rax

Order is %rdi, %rsi, %rdx, %rcx, %r8, %r9. Third = %rdx. (%rax is the return value; %rcx is the fourth.)

Q9. Which of these is a callee-saved register?

  1. %rax
  2. %r11
  3. %rbx
  4. %rcx

Callee-saved: %rbx, %rbp, %r12, %r13, %r14. If a function uses %rbx, it must save and restore it. The others listed are all caller-saved (scratch).

Q10. Which is a correct function prologue (frame setup)?

  1. pushq %rbp ; rrmovq %rsp, %rbp
  2. rrmovq %rsp, %rbp ; pushq %rbp
  3. pushq %rsp ; rrmovq %rbp, %rsp
  4. popq %rbp ; rrmovq %rsp, %rbp

Save the caller's frame pointer first (pushq %rbp), then point %rbp at the new frame's top (rrmovq %rsp, %rbp). Option 4 (popq) is the teardown, reversed.

Q11. A function needs the value in %r10 to still be valid after it calls another function. What must it do, and why?

  1. Nothing — %r10 is callee-saved and is preserved automatically
  2. Pass %r10 as the first argument
  3. Save %r10 itself (e.g. push it) before the call and restore it after, because %r10 is caller-saved and the callee may clobber it
  4. Move %r10 into %rax first

%r10 is caller-saved/scratch, so the callee is free to overwrite it. If the caller cares, the caller saves it.

Section 4 · Array addressing & the smash (your focus area)

For Q12–Q14, a function has a local long buf[4] and %rbx points at buf[0], which is at address 0x400. The stack grows down, so above the array sit the saved %rbp (at 0x420) and the return address (at 0x428).

Q12. What address is buf[3]?

  1. 0x403
  2. 0x418
  3. 0x424
  4. 0x430

3 × 8 = 24 = 0x18; 0x400 + 0x18 = 0x418. (0x403 is offset 3 bytes — inside buf[0].)

Q13. Writing to which index of buf (treating the store as buf[i]) would overwrite the return address at 0x428? Enter the integer i.

Offset = 0x428 − 0x400 = 0x28 = 40. 40 ÷ 8 = 5, so buf[5] — two past the end of a 4-element array.

Q14. Which single instruction, inserted before the function's ret, overwrites that return address with the value in %rax?

  1. rmmovq %rax, 5(%rbx)
  2. mrmovq 40(%rbx), %rax
  3. rmmovq %rax, 40(%rbx)
  4. rmmovq %rax, 0x28(%rsp)

Offset 40 (= 0x28) from the base in %rbx, and it's a store: rmmovq %rax, 40(%rbx) (0x28(%rbx) is the same). Option 1 uses the index as the byte offset; option 2 is a load; option 4 uses the wrong base register.

Section 5 · Directives, encoding & SEQ phases

Q15. What does the directive .quad 0x1F do?

  1. Jumps to address 0x1F at runtime
  2. Reserves 0x1F bytes of space
  3. Defines a label named 0x1F
  4. Emits one 8-byte value (0x1F) into memory at the current position

.quad lays down a single 8-byte (quadword) constant. It's assemble-time data, not a runtime action.

Q16. Encode irmovq $5, %rax as bytes.

  1. 30 0f 05 00 00 00 00 00 00 00
  2. 30 f0 05 00 00 00 00 00 00 00
  3. 30 f0 00 00 00 00 00 00 00 05
  4. 30 05 f0 00 00 00 00 00 00 00

irmovq is 3 0 F rB: byte 0 = 30, byte 1 = F:rB = F0 (rB = %rax = 0), then the constant 5 as 8 bytes little-endian: 05 00 … 00. Option 1 reverses the register nibbles; option 3 is big-endian.

Q17. Decode the bytes 60 31.

  1. addq %rcx, %rbx
  2. addq %rbx, %rcx
  3. subq %rbx, %rcx
  4. rrmovq %rbx, %rcx

Byte 0 6 0 = OPq, ifun 0 = add. Byte 1 3 1 = rA:rB = %rbx:%rcx. Assembly lists rA first: addq %rbx, %rcx (meaning R[rcx] = R[rcx] + R[rbx]).

Q18. (on paper) List the operations in each SEQ phase for call Dest, in course notation.

Reveal the solution 
Fetch:     icode:ifun = M1[PC]
           valC = M8[PC+1]        # no register byte, so valC starts at PC+1
           valP = PC + 9
Decode:    valB = R[%rsp]
Execute:   valE = valB + (-8)
Memory:    M8[valE] = valP        # push the return address (valP)
Writeback: R[%rsp] = valE
PC update: PC = valC              # jump to the target

The two things people miss: valC is at PC+1 (call has no register byte), and what's pushed is valP, the return address.

Q19. Could SEQ execute a new instruction addm D(rB), rA meaning R[rA] = M[D + R[rB]] + R[rA] as a single instruction?

  1. Yes: valE = valB + valC, then valM = M8[valE] + valA
  2. Yes, it's just mrmovq followed by addq internally
  3. No, because it writes two registers
  4. No — it needs the ALU twice (once for the address D + R[rB], once for the final add), but SEQ has one ALU in Execute and no wire to feed valM back into it

The address needs an ALU add in Execute, and the final valM + valA would need a second ALU operation after Memory. SEQ has a single ALU used once, and valM isn't available until after Execute, so there's no path to add it. Name the specific missing resource — "too complicated" earns nothing.

Q20. (on paper) Enumerate the six SEQ phases in order, and say in one line what each produces. Then check against Lesson 3, Part D.

Reveal

Fetch (icode/ifun/rA/rB/valC, valP) → Decode (valA, valB) → Execute (valE; sets CC for OPq; Cnd for jXX/cmov) → Memory (valM on a read, or a write) → Writeback (port E ← valE, port M ← valM) → PC update (PC ← valP/valC/valM).
